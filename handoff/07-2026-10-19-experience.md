## 1. 中键：以 Windows 实测为准

**当前 Windows 协商路径使用 Win32 MK_* 按钮值：左键 1、右键 2、中键 16 (`MK_MBUTTON`)。**

旧 GUI 发中键 `3`，且只在 `middle_clicked()` 后补发一次按下/抬起，导致中键失效、
按住拖动无法表达。本轮初期参考 Mac 路径推断过 `4`，实测推翻了这个推断，最终代码使用 16。

在 KVM-WIN11 的交互桌面运行 WinForms 事件验证窗口，依次用 `pointer_check` 发送
`1/2/3/4/16`：1 收到 Left、2 收到 Right，3/4 没有 Middle 事件，16 收到 Middle。
随后单独发送 16，远端记录：

```text
down Middle 2026-10-19T02:47:50.1618966Z
drag 270,111
up Middle 2026-10-19T02:47:50.9317244Z
```

工具：`crates/uu-core/examples/pointer_check.rs`，限制只向唯一测试机发送：

```bash
UU_FORCE_JOIN=0 cargo run -p uu-core --example pointer_check -- aeawvmepembcpca5 16
```

`crates/uu-gui/src/input.rs` 现在消费原始 PointerButton/PointerMoved 事件：

- 中键真实按下、按住拖动、松开，不再等 click 才合成一对事件。
- 三键都跟踪 held 状态，在画面外松开、失焦、断开时释放，黑边和工具栏不发按下。
- 只在指针变化时发移动，滚轮保留方向/幅度，并支持横向。
- 设置弹窗和“观看模式”不转发输入。
- `UU_INPUT_AUDIT=1` 仅输出鼠标按下/抬起和按钮值，便于确认 GUI 发出的消息。

低层鼠标 hook / GetAsyncKeyState 在这条注入路径没记录到中键，不能作为唯一验收手段；
WinForms 的实际 MouseDown/Move/Up 事件已提供正向证据。
本机原始记录：`artifacts/experience-validation/windows-pointer-events.txt`。

## 2. 参考版 GUI

主要 UI 移到 `crates/uu-gui/src/ui.rs`。根据用户截图改成浅色背景、自绘标题栏、
蓝色信息卡、设备侧栏、在线徽章、桌面预览卡和功能行。设备 ID 收入菜单，状态文字收到底部。

- “进入桌面”和“观看模式”可用，文件/终端/端口映射等未实现项目置灰。
- API 的 KVM-WIN11 `wallpaper_url` 实测为空，所以该设备使用绘制的蓝色背景；
  没有提取/分发官方二进制中的专有图像。已有 wallpaper_url 的设备仍展示实际图片。
- 串流时切成黑色画布和紧凑工具栏，设置放弹窗，HUD 默认隐藏，保留 F1 / Ctrl+Alt+F。
- 启动按当前显示器逻辑尺寸收敛窗口大小；Windows exe 改为 GUI 子系统，避免附带控制台。
- 修饰键在相关按键前同步，避免同一帧快速 Ctrl+C 等组合键顺序颠倒。
- 连接初始化结束后补发 GUI 中选择的画质/码率，避免被 core 初始设置覆盖。

## 3. 串流链路

新 `crates/uu-core/src/video_receiver.rs` 提供有限时间/内存的 RTP 重排与完整 AU 组装。
旧代码存在按到达顺序拼 FU-A、时间戳变化后发送不完整 AU、FU 状态跨帧残留的问题。
现在丢弃缺片、缺 marker 或格式错误的帧，处理序号/时间戳回绕和迟到/重复包。

- **NACK 旧代码已有**：webrtc-rs 默认 interceptor 注册了 NACK；不是从零新增。
  默认 100 ms 间隔本轮改成 20 ms。实际重传效果仍需专项抓包确认。
- `UU_JITTER_MS` 缺包等待默认 60 ms，可设 10–200；顺序完整帧不额外等待。
- 坏帧触发 PLI/FIR，500 ms 限速重试；健康串流不再每两秒强制 IDR，REMB 独立发送。
- 默认平衡恢复：跳过坏 AU，但继续解后续完整帧并请求 IDR；解码报错/压缩队列溢出
  则暂停依赖帧，等真正的 IDR。
- `UU_STRICT_RECOVERY=1` 可在任意丢帧后暂停到 IDR。实机测试这种策略在高损耗下
  会显著降低输出帧率，所以最终没有默认启用。平衡恢复仍可能有短暂参考帧误差。
- 关键帧识别改成真正 type-5 IDR，不能把 SPS/PPS 当成恢复点。
- 阻塞解码/颜色转换移出 tokio 收包线程；压缩队列最多 8 帧；积压时仍解参考链，
  但只对最新图做 RGBA 转换。
- `display_frames.rs` 按屏幕保留最新一张待显示图片，不再无限堆积 RGBA。
- HUD 区分缺包、坏帧、重排、迟到/重复、队列溢出与解码错误；显示恢复请求和等待状态。
- SDP 只声明实际接收的 H.264/Opus，不声明尚无恢复实现的 ULPFEC。

详细机制、Sunshine/Moonlight 一手参考和下一步见 `docs/streaming-quality.md`。
**没有宣称接通 FEC 或完整 RTX，也没有宣称已消除所有花屏/停顿。**
