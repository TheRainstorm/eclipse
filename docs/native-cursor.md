# Windows 原生串流光标

新 Windows 主机可独立传输远端光标。客户端的“输入 → 光标显示”提供三种模式：

| 模式 | 画面中的远端光标 | 客户端光标 |
| --- | --- | --- |
| 本地和远端光标 | 显示主机实际位置和形状 | 保持本地即时反馈 |
| 仅远端光标 | 显示主机实际位置和形状 | 鼠标进入视频时隐藏，进入本地菜单时恢复 |
| 隐藏光标 | 不合成独立远端光标 | 鼠标进入视频时隐藏，进入本地菜单时恢复 |

Ctrl+Alt+C 循环切换模式。窗口失焦或打开菜单不会停止显示远端光标，但仍按已有规则释放远程输入；改变光标显示不授予输入权限。

两端需要支持新能力。旧 Windows 主机未提供独立光标时，“仅远端”不可选，已保存的此模式会保留本地光标作为回退。UU 官方兼容串流继续使用原有协议；Linux 门户把光标嵌入视频的行为也保持原样，不将 Windows 扩展描述为所有平台都支持独立光标。

## 数据路径与延迟

DXGI 捕获所有者在成功取得帧后读取位置和形状，再判断是否存在新桌面图像。因此只有光标变化的通知也会更新光标，不会被误送成新视频表面。

位置以源输出的物理像素表示，客户端按视频实际绘制区域缩放，适用于输出缩放、留黑边和不同 DPI。DXGI 提供的是形状左上角位置，绘制远端光标时不再减热点；热点仍随形状传输。[Microsoft 的位置说明](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ns-dxgi1_2-dxgi_outdupl_pointer_position)、[Desktop Duplication API](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)。

形状仅在变化时压缩分块发送，位置由变化事件立即唤醒发送；背压时保留最新状态。独立 SCTP 流有消息、形状尺寸和缓冲上限，不向视频或键盘队列追加光标事件。断线、显示器重选和桌面失去访问权限会清空当前光标，旧连接的迟到消息不能更新新连接。

客户端在既有视频绘制调用中合成两张小纹理，分别表示颜色/透明度和 XOR 操作，支持彩色、单色 AND/XOR 及 masked-color 光标。RGBA 兼容路径只重建光标覆盖的小区域，不读回或复制整张 GPU 视频。[Microsoft 的形状语义](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/ne-dxgi1_2-dxgi_outdupl_pointer_shape_type)。

这增加少量光标采集、传输和合成工作，没有为视频增加编码、读回或等待队列。“仅远端”仍需等待输入到达主机并收到实际位置；“本地和远端”保留客户端即时反馈。不能把本地光标跟手当作端到端视频延迟，也不能据此承诺零性能开销。

若应用或驱动已经将光标画入桌面视频，客户端无法从编码后的画面中移除它；“隐藏”控制的是独立光标。采集按平台报告决定是否另行叠加，避免重复绘制。

## 验证入口

`cargo test -p uu-capture --lib cursor` 检查形状、遮罩和生命周期；`cargo test -p uu-core --lib native_cursor` 包含真实加密 SCTP 传输、位置覆盖、隐藏、重建和关闭检查。

`video_cursor_probe` 使用生成的图案，在独占的测试显示中检查 GPU 合成及 RGBA 回退，包括热点不重复扣除、比例缩放和边缘裁剪。它不会读取用户屏幕或发送输入。这些检查不替代实际桌面交互验收。
