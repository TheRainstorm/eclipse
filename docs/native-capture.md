# 原生被控端采集进度

原生局域网模式正在分阶段实现；桌面采集后端不等于已经交付网络被控端。兼容客户端不依赖这些采集接口。

## X11

`uu-capture` 已支持已授权 X11 会话的显示器与窗口采集：RandR 活跃显示源与主屏、显式显示源选择、真实 BGRA 像素、行对齐及颜色掩码处理。当前使用 GetImage，不宣称共享内存或零拷贝。

在真实 X11 会话里可运行：

```bash
cargo run -p uu-capture --example capture_probe -- --list
cargo run -p uu-capture --example capture_probe -- --output /tmp/new-capture.ppm
```

诊断必须显式提供一个不存在的输出文件；不会默认保存画面，不覆盖已有文件。Unix 输出权限为600。`--monitor`按枚举名称选显示器，`--window`指定本机窗口ID，`--frames`最多300帧。

`--x11-display` 仅用于明确选择自己管理的 X11 会话，例如隔离测试服务器。

## Wayland

当前开发分支通过系统 ScreenCast / RemoteDesktop 门户请求授权，使用同一会话的 PipeWire 视频流与输入接口，不把 Xwayland 根窗口当作真实桌面。系统选择器决定实际显示源；界面中的门户源是重新打开选择器的入口，不是提前枚举的物理屏幕。

设备验证后等待系统选屏时，客户端显示正在等待被控端共享屏幕并准备编码。请在被控端完成系统选择；此时网络验证已完成。取消会显式关闭待处理的选屏请求；门户初始化与授权共用 120 秒准备期限。若门户后端自身阻塞，仍可能需要在被控端取消系统选择器。

请求键鼠权限时要求门户同时支持键盘和指针；不支持或用户未授予输入时继续只读采集，不通过额外输入设备绕过授权。组合 RemoteDesktop 屏幕选择不请求持久化恢复，停止共享、取消及超时关闭自身门户会话。重新选源需要系统再次授权。当前只接收可映射的 CPU 帧，不宣称 DMA-BUF 零拷贝或无人值守访问。

构建需要 PipeWire 开发包，运行时需要可用的桌面门户实现。隔离门户/PipeWire 夹具已覆盖授权、拒绝、取消与只读降级；真实桌面选择器和输入仍需在目标合成器上验收。

## Windows

已支持当前交互会话的 DXGI Desktop Duplication：枚举活跃显示器、按名称选择、D3D11 staging 读回、行对齐与旋转修正。采集不会启用虚拟显示器、改变主屏或关闭其它显示器。

同一诊断程序可在 Windows 运行，`--list` 列出当前显示器，`--monitor` 选择枚举出的名称。请只在自己有权限的桌面执行；服务会话、锁屏、安全桌面或不支持 Desktop Duplication 的驱动可能拒绝采集，程序会返回错误，不提升权限或更改桌面配置。布局变更或 DXGI access lost 后需要重新打开采集。

当前路径是 SDR BGRA 的 CPU 读回，尚未提供硬件编码直连、HDR 色调映射、窗口采集与独立光标合成；不能把它当成最终的高性能主机实现。

## 软件编码与验证

原生软件路径使用 OpenH264 屏幕内容编码，显式配置目标码率、帧率和全范围 BT.601 的 VUI；输入转换与声明一致。编码参数接受 1–240 FPS，目标帧率不代表处理性能保证，分辨率与帧率组合仍须符合 H.264 level 5.2。原生客户端可在现有串流内调整帧率和码率，更新采集节奏与编码参考链；Windows 使用 GPU 编码时继续保留 GPU 输入路径。兼容客户端接收官方主机仍使用其独立协议。

修改码率会重新创建编码器，并以 IDR 建立新的参考链。码率受画面复杂度影响，预算不足时允许编码器跳过源帧，不保证每秒发出指定数量的帧。并发恢复请求只安排下一次 IDR，避免连续关键帧加重拥塞。

`uu self-loop --fps 60` 可在本机回环上验证合成采集、编码、分包、解码与画质；这个测试命令只绑定本机回环地址，不是可供远程连接的原生主机。实际网络模式还需要配对、加密信令与输入权限。
