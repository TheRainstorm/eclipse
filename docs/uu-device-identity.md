# UU 设备名称、注册身份与设备管理

从 0.14 起，UU 显示名自动采用“电脑名-Eclipse”，与服务端原生共享名称独立，方便区分官方客户端。名称只用于显示，不参与配对认证；改名不更换 UU 编号、原生公钥或授权记录。

“服务管理 → 连接服务 → UU 账号 → 更新注册信息”更新本机真实操作系统、主板、CPU、显卡、网卡与内存资料。初始化接口会更新硬件，但保留已有显示别名，因此名称另用认证后的改名接口同步。软件只使用本客户端安装身份；若服务返回不同编号，会拒绝覆盖原身份。

扫码前，有效登录态可以先更新旧名称。没有有效登录态的旧设备在手机首次确认页可能仍显示旧名，登录确认后再自动更新；失败会显示提示并允许重试，不丢弃已成功的登录。新注册从一开始即使用带后缀的名称。

## 与官方客户端共存

当前实现不读取或复用官方客户端的注册资料，而是在自己的用户配置中保存独立的注册身份。

| 项目 | 同一电脑上的官方客户端与本客户端 |
|---|---|
| UU 编号 | 通常是两个独立的注册编号 |
| 显示名称 | 可以相同；本客户端默认使用电脑名-Eclipse |
| 登录与上线 | 分别登录；本客户端在启用 UU 共享入口时接受原生连接 |
| 原生授权 | 由本客户端保存，与官方设备绑定独立 |

所以，同一电脑可能在 UU 账号里出现两条同名记录。这不是仅凭名称就能合并的重复项，选择哪个编号就连接哪个服务。我们没有用官方身份来替换本客户端身份的功能。

两种实现的信令身份分开，不会仅因名称相同而抢用同一个设备编号。若双方都启动共享，会分别发布自己的设备；同时采集、编码或处理远程输入仍可能竞争 GPU、CPU 或输入资源，也受 UU 账号和服务自身规则影响。当前没有完成官方端与原生端同时共享的实机冲突验收，不能保证所有组合完全没有影响。无需同时提供两种共享时，可只在需要的客户端开启共享。

## 管理与解绑

打开“连接服务 → UU 账号 → 管理 UU 设备”，可查看当前账号绑定的设备及编号；本客户端的注册条目标记为“本客户端”。列表包含本账号的官方设备，不把别人共享给你的设备列为可解绑目标。

点击“解绑”后，确认框会再次显示设备名称和编号。只有点击“确认解绑”才提交请求；提交前会重新获取当前账号列表确认目标。软件不会自动清理看起来重复的设备。解绑本客户端会退出本客户端的 UU 登录；若当前共享启用了 UU 入口，也会停止该次共享。仅使用 IP / VPS 的共享不因此停止。

这里的删除是**解除 UU 账号绑定**，不是卸载软件，也不是清空本机注册资料。被解绑的客户端再次登录后，可能重新出现在账号设备列表中。解绑不会删除本项目保存的原生公钥、配对授权或 IP / VPS 连接配置；如需撤销原生控制权限，应在“服务管理 → 输入 → 已授权的控制端”撤销对应设备。

名称更新请求与账号解绑请求的协议格式已经核对；真实手机显示和本版本认证解绑仍需实机验证。自动化验证覆盖列表归属、重复条目合并、错误拒绝、输入校验和账号切换时丢弃旧操作结果，没有替用户实际解绑任何设备。
