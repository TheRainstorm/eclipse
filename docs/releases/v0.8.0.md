# uu-client 0.8.0 · Linux 硬件互通与媒体观测

修复原生 Linux 硬件编码码流被硬件解码器拒绝后回退软件的问题，减少首帧等待和 BGRA 转换开销，同时修正停图统计与调试数据落盘行为。默认原生编码仍为软件；这些编码改进不会改变 UU 官方被控端的编码器。

## 迟到补包与防重放

- 两种模式的SRTP接收窗口匹配现有2048包重排上限，避免缺包落后数百个序号后，有效NACK补包在解密层过早被拒绝。帧修复时间上限保持不变。
- 修复首次迟到的上一轮序号未被正确标记的问题，使用有界环形位图；只在认证成功后记账，重复包和超出窗口的旧包仍被拒绝。加密与认证算法、SRTCP选择不变。
- 本机UDP中继在解密前丢包，通过真实加密RTCP请求补发，验证篡改拒绝、有效补包交付及重复补包拒绝。两种加密配置和跨回绕检查、完整索引参考模型共同验证，不访问真实桌面。详见[恢复说明](https://github.com/TheRainstorm/eclipse/blob/master/docs/stream-recovery.md)。

## 原生硬件路径

- 编码端按真实的 Constrained Baseline、单参考 I/P 结构补齐 SPS 约束与零重排声明。解码参考面继续保留，不用清空参考链来降低等待。
- VA-API 解码兼容完整 NAL 后的 Annex-B 全零尾部填充，避免有效码流被误判为缺少下一个 NAL；其它解析错误仍报告。
- BGRA 输入复用已有 OpenH264 的像素转换与 SIMD 选择，直接产生有限范围 BT.601 数据，缓存按会话复用。非整像素行距、I420 和 NV12 保留原有转换路径。
- 同一设备两轮交错对比中，合成4K BGRA编码调用均值约49.1→27.6 ms，720p约6.46→4.10 ms；包括转换、上传和等待，不能据此承诺4K60或端到端延迟。
- 硬件探针可用 `--decoder hw` 直接验证硬件，无自动软件回退掩盖故障；检查连续解码、全新软/硬解码器恢复、色彩、裁剪、码率调整与合法零填充。

实机双 VA-API 合成串流600帧、零解码错误，并通过合成音频冗余恢复检查。720p、4K、1918×1078裁剪与竖屏硬件探针通过。单次接收端首帧观测约350→55 ms，不表示所有设备或真实桌面的端到端改善幅度。

## 观测与桌面提示

- 视频停止出帧后，解码FPS按持续计时归零，不继续显示停止前的帧率；最近一次解码耗时保留。真实隔离暂停/恢复测试验证了归零和恢复。
- `UU_MEDIA_DEBUG=1` 只输出媒体诊断，不再自动把解码画面保存到公共临时目录。0.7及更早版本仍有旧行为；已有文件不会被升级自动删除。显式码流导出是独立选项。
- Wayland会话的原生共享设置说明当前仅支持可访问的X11显示源；完整portal采集尚未接入。
- 原生冒烟测试可指定并核对实际编码后端，同时报告实际解码后端，保留软件默认测试与旧CLI兼容。

## 安装与限制

使用本版本的Windows ZIP或Linux tar.gz，核对`SHA256SUMS`后运行安装器。保留登录态、偏好和用户覆盖配置；旧窗口需重新打开才能使用新程序。

媒体协议仍为v1。Windows原生主机仍使用软件编码；Linux硬件路径仍含CPU转换和上传。没有增加H.265、AV1、HDR、视频FEC、Wayland portal、公网发现或运行中切屏。上游依赖整包开发测试夹具仍受旧接口限制，不把它计为通过；本项目测试和实际硬件探针分别验证。
