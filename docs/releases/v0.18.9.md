# v0.18.9：修复外屏 Render 高延迟与悬浮输入菜单

修复 Windows 混合 DPI 多窗口下反复转换、上传完整字库的问题。不同缩放比例使用独立的字库 GPU 缓存，未变化的图集直接复用；新增字形、字体替换和采样参数变化正常更新，不修改系统缩放、显示器配置或视频画质。

在一组 Intel UHD 客户端、内屏150%/外屏100%、H.264 1080p60 的外屏窗口实测中，原 Render 约12ms，修复后约130秒采样的稳态窗口均值中位值为 **2.65ms**，视频帧邮箱等待中位值为 **0.48ms**，解码错误为0。该结果是 UI CPU 与客户端阶段测量，不能当作端到端延迟，也不扩展为所有显卡、AV1/HDR、全屏或长期稳定性验收。完整前因后果、同进程反转对照与脱敏采样见[混合 DPI 外屏延迟报告](../performance/mixed-dpi-render-latency.md)。

同时修复悬浮菜单“输入”入口随鼠标进入、离开而消失的问题。“输入”和“安全”按远端输入能力显示，菜单中暂停转发或临时释放控制不再隐藏入口；实际键鼠与手柄发送仍遵循授权、焦点、仅观看及本地菜单归属。

本版还汇总此前本地 0.18.8 及其后续修复：

- Windows 原生 SDR 编码前使用明确的 GPU 色度滤波与采样位置，改善细小文字彩边；NV12 呈现显式处理色彩矩阵、范围和可见边界。仍为有损 4:2:0 视频，不能保证细彩色无损还原。
- 按每次 HDR 协商选择主机采集格式；SDR 请求不再无条件进入 HDR 捕获。Windows HDR/SDR 前提见 [HDR 说明](../hdr.md)。
- 修复混合 DPI 下原生绝对鼠标随位置增加的比例错位。
- 修正 Intel MFT AV1 序列色彩声明与实际输入不一致造成的首帧失败，并补充原生准备、会话结束的失败原因。
- 绘制前核对窗口实际交换间隔，避免恢复策略时额外触发重绘；保留 Render 原计时范围，增加按视口、视频回调和 OpenGL 调用分组的诊断。
- 默认启用已验证的 AMD AMF 输入表面复用，包含主机逐帧测量，以及此前连接、采集、输入菜单和 Windows HDR 更新；范围与限制见 [0.18.8 本地迭代说明](v0.18.8.md)。其它未晋级的采集重叠、独立设备、QoS、专用 UDP 接收等实验保持关闭。

已知范围：PixPin 首次截图导致全屏窗口变化的问题本次仍未解决；没有宣称达到 Sunshine/Moonlight 的整体延迟与稳定性目标。诊断中不同窗口均值的合计不是同一帧端到端延迟。

Windows 使用完整 ZIP 中的 `install.ps1`，Linux 使用完整 tar.gz 中的 `install.py`。保留本地账号、配对和设置；关闭旧主页与串流窗口后重开生效。外屏字库和悬浮输入菜单修复发生在客户端，更新客户端即可使用；完整主机诊断和编码侧修复需要相应更新被控端。发布包附带源提交清单、逐文件 SHA256 和 `SHA256SUMS`，旧发布资产保持不变。
