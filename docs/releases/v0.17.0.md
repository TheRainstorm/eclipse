# v0.17.0：突发参考链恢复、诊断与 AMF 稳定性

包含 [v0.15.1](https://github.com/TheRainstorm/eclipse/releases/tag/v0.15.1) 和 [v0.16.0](https://github.com/TheRainstorm/eclipse/releases/tag/v0.16.0) 的功能与修复。本版是已完成优化的发布，不代表全部低延迟和稳定性目标已经完成。

- 按实测解码工作量与字节预算接纳完整压缩帧，硬上限 64 帧 / 64 MiB；保留突发中的参考链，仅跳过过时画面的呈现工作。十二帧加密突发回归中 44 帧全部解码，旧固定八帧队列会失败。
- 收到恢复请求后，在下一捕获帧重建编码参考链，移除主机额外 250ms 等待；保留请求合并和接收端反馈限频。
- HUD、图形端诊断和 CLI 分别统计网络数据损坏、解码队列压力、解码错误、格式切换四类恢复原因，便于区分网络和解码瓶颈。
- 长会话诊断保留起始段和七段近期轮转记录，每段最多 256 KiB、单会话最多 2 MiB，后台非阻塞写入；不再达到原文件上限后永久停止记录。
- 修复 AMF CPU 输入在长时间 4K 编码时的驱动访问违例：使用框架分配的 NV12 平面和实际行距管理上传。GPU 输入仍保持同设备纹理路径，不因此增加 CPU 回读。

## 已执行验证

- Windows 原生媒体、核心和 GUI 回归分别 92、226、140 项通过；另有三个隔离实窗测试通过，覆盖输入捕获和真实双生成会话工作区。
- AMD AMF → Intel D3D11VA 的加密跨机生成 3840×2160 图案，共解码 18000 帧，零解码错误、零队列丢帧。AV1 基线 10800 帧约 185 秒，实际接收采样中位约 58 FPS。
- AV1 / HEVC 各 3600 帧，每十秒注入 120ms 丢包并丢弃对应重传，各完成六次网络数据损坏恢复，CLI 最长图像间隔约 250 / 243ms。这不是 FEC 测试或物理屏幕端到端延迟。
- AMF CPU 输入旧实现可复现驱动崩溃，修复后 1200 帧及上述跨机长测通过。

## 尚未实现与待验收

- **视频 FEC、Sunshine 式发送端包节奏、按需无限 GOP、原生 NVENC 尚未实现**；仍使用已有 NACK / 重传与 PLI / FIR 恢复，周期 GOP 没有改变。HDR 未实现。
- 不保证所有卡顿已解决，也不保证 4K60 锁帧。用户实际 DXGI 桌面采集、GUI 呈现、全天长稳和端到端延迟仍需验收。
- Win+V 松开 Win、双层客户端快捷键透传、NVIDIA 参数实机及跨 NAT 新配对的完整实流仍待验收。
- 远程服务管理、厂商编码参数及配置版本的范围沿用 v0.16.0 说明。主机和客户端建议同时升级。

Windows ZIP / Linux tar.gz 及 `SHA256SUMS` 随本版提供。升级保留本地设置和授权；关闭旧主页与串流窗口后启动新版。
