# v0.19.4

修复实验编码初始化、HDR 文字彩边和 HUD 的刷新率与菜单布局，并减少视频帧触发的重复绘制。

- PyroWave 不再因保存了 AMD balanced 或其它传统硬件编码调优而拒绝初始化。这些厂商参数不适用于 PyroWave；SDR、4:2:0、CBR 和固定帧预算的限制仍保留。
- HDR P010 编码采用左对齐色度和线性光预滤波，解码按相同位置重建并限制到可见区域，减少细文字、图标边缘的绿色或彩色阴影。4:2:0 仍会损失细小彩色细节。
- 视频邮箱发布只请求一遍绘制，普通控件仍使用原有的界面稳定重绘。HDR 关闭垂直同步时，按驱动能力同时配置 DXGI 交换链和呈现标志；不支持的设备回退原模式。
- Windows 主机传递实际显示器刷新率，HUD 不再把未知值显示为 0 Hz；旧主机或不提供刷新率的平台显示缺省。
- 延迟拆分补充 `net/que`，中文悬停显示“采/编/解/渲/网/排”；网络行移除重复的单程字段，保留 RTT、原始与修复后丢包。
- HUD 子菜单移到“更多 → HUD”，保留 Compact / Detailed 两档与中文十行悬停详情。子菜单与父菜单共同阻止指针透传。

客户端和主机都要更新，后台共享也要使用新版进程。完整退出旧主页及串流窗口后重新打开；只替换正在运行程序的文件不会更新内存中的代码。

`rnd` 是绘制准备和提交的 CPU 墙钟时间，可包含驱动等待；不是 GPU 执行时间或显示器扫描延迟。高帧率、HDR、窗口尺寸和同时运行的串流均会影响结果。没有固定的 120 FPS 渲染上限，也不保证所有设备稳定绘制 165 FPS。实测需同时比较新帧绘制率、CPU 与 Present，不能把阶段之间的等待转移当作延迟下降。

HDR 生成图与独立 CPU 参考、原生浮点目标切换可以验证采样、亮度与资源生命周期；用户截图中的最终视觉效果仍需安装后确认。被实机对照发现增加 WGL 等待的直接共享缓冲方案已撤回。
