# v0.18.8：AMD 编码输入复用与串流诊断

Windows 原生被控端默认启用 AMD AMF 编码输入表面复用，减少逐帧创建转换目标纹理和视图。只有对应帧输出完成、编码器真正释放输入后才能再次使用；设备重建和异常会结束旧代次。普通 SDR 与 HDR 转换路径使用同一套有界所有权规则。

在固定的 4K60、AV1 SDR、约 40 Mbps 对照中，主机从采集就绪到发送队列出队的平均时间由 6.26–6.38 ms 降到约 5.56 ms，改善约 11%–13%；后续一次复核为平均 5.585 ms、P99 6.917 ms。该指标不包含完整网络、客户端显示与输入反馈时间，不代表端到端延迟，也不保证其它设备获得同样收益。

其它更新：

- 增加有界逐帧测量，以源帧身份和输出 PTS 关联采集、编码、发送队列及 RTP 写入；区分新画面与重复画面，保留样本覆盖和丢失信息。详见[逐帧测量说明](../frame-tracing.md)。
- 修复 Windows 仅鼠标更新时错误处理采集纹理的问题；切换显示器保留当前码率和帧率。
- 支持原生采集协议的 Wayland 合成器直接共享指定显示器，其它桌面继续遵循系统门户授权。
- 串流输入菜单集中管理光标、指针与手柄设置，支持隐藏光标及快捷键。
- 包含 Windows 原生 HDR10 串流、HDR 桌面到 SDR 的亮度映射及实际 HDR/SDR 状态显示，详见[HDR 说明](../hdr.md)。Linux 当前仍使用 SDR。

本次仅启用已验证的 AMF 输入复用；采集重叠、独立设备、专用 UDP 接收、QoS 等实验保持关闭，未纳入单帧 VBV 实验。需要排查 AMF 兼容性时，可以在被控端进程启动前设置 `UU_AMF_INPUT_POOL=0`，恢复每帧独立输入目标；删除该变量即可恢复默认复用。

已知限制：最新一次 60 秒对照没有超过 50 ms 的绘制间隔，但仍记录到重传请求和显示跳帧，不能据此认定卡顿已经全部解决。尚未验证达到 Sunshine/Moonlight 的整体低延迟与稳定性目标；完整客户端/GPU/显示阶段计量和后续重构仍未完成。

更新方式：Windows 使用完整 ZIP 中的安装器，Linux 使用完整 tar.gz 中的 `install.py`。两端与 Windows 后台服务均更新后重新连接；旧端仍可串流，但完整新诊断需要两端支持。关闭正在使用的旧进程后安装，安装器保留本地配置。无需修改系统显示设置才能使用输入复用；HDR 的系统前提见 HDR 说明。
