# v0.10.0：Eclipse 局域网与 Windows 低延迟接收

本版本收录现有功能与已验证修复。Eclipse 局域网主机和 UU 兼容被控端是两条独立通路，支持的编码与输入能力以各自说明为准。

- Eclipse 局域网发现、手动添加地址、首次配对确认与持久授权；已配对设备可打开独立串流窗口。共享由主机明确启用，可撤销授权、断开当前串流，退出时清理监听和会话。
- 原生共享显示真实采集、编码与声音状态；提供系统声音、双方许可的文本剪贴板，以及 Windows/Linux 生成视频双向连接与复连验证。修复两端系统时间不同导致新邀请被误判过期的问题。
- Windows UU 接收采用 D3D11 GPU 颜色转换和 WGL 共享纹理，减少同步读回及上传；延后归还纹理读取所有权，保留颜色、裁剪、租约和失败回退。实际 4K 会话的解码调用耗时由约 8ms 降至约 0.5ms，此数值不代表端到端延迟。
- Windows UU 串流可选择优先 H.265 / HEVC，统一能力声明、协商、RTP 组帧与 GPU 硬解；保留 H.264 后备。两块 GPU 的加密同轨道 H.264/HEVC 切换测试通过，用户实际 4K60 HEVC 重连后稳定。
- 修复 TWCC 反馈发送阻塞视频接收及高包速率下反馈时间逐包截断失真；视频接收期间提高 Windows 定时精度，并在结束时释放。
- 串流统计区分控制 RTT、解码、待绘制和呈现提交，增加源/到达节奏及 RTT 分位诊断。“已知段合计”仅覆盖部分阶段，不能作为鼠标输入到屏幕的完整延迟。
- 修复首次全屏时 Win/Alt+Tab 等系统快捷键捕获延迟，统一输入归属与本地控制命令。浮动入口支持拖动与靠边收起，多显示器标签保留本地顺序。
- 保留 Linux VA-API 下载优化与 GPU 平面颜色转换。实验性 DMA-BUF/EGL 直接呈现仍需显式启用并按设备验证。

优先跟手的 Windows 用户可在设置中关闭垂直同步、重开串流窗口比较；实际局域网对照已有明显改善，但仍可能有撕裂，且没有完整端到端延迟测量。

已知限制：H.264 4K60 在部分高码率场景仍不满帧；HEVC 首次同轨道切换曾出现 30FPS，退出重连可恢复 60FPS，初始化原因待查；接收/解码达到 60FPS 不代表呈现每帧达到 60FPS。Eclipse 原生主机仍以单显示源、单会话为主，Windows 硬件编码、HEVC/AV1/HDR、Wayland 主机及视频 FEC 尚未实现；这些原生主机限制不代表 Windows UU 接收端缺少 HEVC。

验证范围包含 Linux/Windows 单元及原生回归、生成视频 GPU 颜色/生命周期检查、两端加密切码，以及用户已反馈的真实串流交互。CI 与合成检查不能替代所有显卡和真实桌面环境的验收。
