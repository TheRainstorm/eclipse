# uu-client 0.4.0 · 原生系统声音与采集性能

原生局域网串流加入系统声音，继续使用自有配对与加密媒体通路，无需 UU 账号或第三方服务签名密钥。

- 主机“共享此设备”增加“共享系统声音”，默认关闭。Windows 采集默认输出的 WASAPI loopback，Linux 采集 PulseAudio / PipeWire Pulse 输出 monitor，不使用麦克风作为备用来源。
- 48 kHz 立体声、10ms Opus 音轨，支持本地音量、静音与 Ctrl+Alt+M；采集设备临时失效时视频继续，后台重试声音采集。
- 双方支持时使用 RFC 2198 RED 携带前一音频包，恢复孤立丢包；队列保持有界，保留 FEC/PLC 与短渐变回退。该功能属于音频恢复，视频仍使用 NACK/RTX 和关键帧恢复。
- Windows DXGI 在已有桌面缓存时非阻塞查询更新，避免帧率等待叠加；定点 BGRA→I420 转换减少 CPU 开销。软件编码实际帧率仍受桌面内容和 CPU 性能限制。
- `native-probe --report NEW.json` 输出私有逐秒视频、网络与音频指标；诊断模式只解码声音、不播放或保存 PCM。主机 CLI 结束时输出采集、编码与发送排队耗时。
- 增加加密音频丢包、独立虚拟音频输出与 Windows/Linux 双进程 CI 检查；与 0.2 / 0.3 双向视频互通。

## 使用

下载对应平台的 ZIP 或 tar.gz，以 `SHA256SUMS` 校验后安装。Windows 先退出旧客户端，解压运行 `install.ps1`；Linux 解压运行 `python3 install.py`。安装器保留本地账号和偏好。

主机选择“共享此设备”，勾选声音并按需允许键鼠控制，选择显示器与主机自身的局域网地址，再将邀请文件私下交给控制端。控制端通过“使用原生邀请”连接；默认仅观看，键鼠控制需主机许可并由控制端申请。详见[原生串流](https://github.com/TheRainstorm/uu-client/blob/master/docs/native-streaming.md)与[系统音频](https://github.com/TheRainstorm/uu-client/blob/master/docs/native-audio.md)。

## 验证与范围

实机验证包括 Windows DXGI / WASAPI 到 Linux VA-API，系统音频设备断开后重建，隔离播放、静音与恢复，以及跨机器视频周期丢包和音频20%定期丢包。测试结果不代表所有网络或硬件条件下的保证；RED 的单包冗余不能覆盖任意连续丢包。

原生模式仍为单控制端、单显示源的软件 H.264 编码（1–60 FPS），尚无原生剪贴板、运行中切屏/画质、硬件编码、HDR、Wayland portal 采集、公网发现或无人值守管理。UU 兼容模式保持独立，需自行配置有权使用的本地连接凭据；发布包不含第三方生产密钥。

Linux 包基于 Ubuntu 24.04，需要兼容的 glibc 和图形/音频库；Windows 包未做 Authenticode 签名。原创代码采用 MIT OR Apache-2.0，第三方组件保留原许可。本项目非官方，兼容接入的协议和知识产权事项见仓库说明。
