# v0.18.1：修复 AMD H.264 在 Windows 的解码回退

AMD 原生 AMF 的 H.264 编码改为请求 Constrained Baseline。此前请求的普通 Baseline 没有设置 Main 兼容所需的约束位，Windows H.264 MFT 可能采用较高 CPU 用时的回退路径，同时仍返回 GPU 纹理，因而仅检查输出纹理不能发现它。

修复通过 AMF 原生 profile 配置生成符合约束的码流，不改写解码输入，不降低 H.264 level。其它编码格式、码率和按需关键帧策略保持原有规则。已有会话需重新连接，编码端需升级。

隔离的同一组 630 帧 4K 生成码流对照中，普通 Baseline 的 MFT 调用约18.8ms/帧、进程 CPU约10.6秒；请求 Constrained Baseline 后约2.1ms/帧、CPU约0.2秒，输出为带 D3D11_BIND_DECODER 的纹理数组，630帧全部解出。单独改变 level 和启用原有 SPS 丢帧修补不能消除回退。该对照不含真实桌面、网络和呈现，不能作为端到端延迟。

Windows 的 H.264 DXVA 约束见 [Microsoft 解码器文档](https://learn.microsoft.com/en-us/windows/win32/medfound/h-264-video-decoder)。其它功能、锁屏与官方 UU 实机验收边界继续见 [v0.18.0](v0.18.0.md)。正式发布附同提交 Linux、Windows 完整安装包与 SHA256SUMS。
