# 产品方向：Eclipse / 日蚀

品牌更新：v0.21.0。以下阶段计划与能力表保留 2026-10-21 的历史规划，当前交付以 [README](../README.md) 和 [发布记录](releases.md) 为准；路线图不承诺完成日期。

## 目标与实施顺序

v0.21.0 起产品统一命名为 **Eclipse / 日蚀**，将原生采集、客户端、配对与自托管网络整合为主程序，UU 兼容功能作为独立插件提供。希望结合 UU 的桌面交互体验、Moonlight 的低延迟呈现和 Sunshine 的采集编码能力。

先把现有用户每天会用到的连接、画面、声音、输入、剪贴板、多屏和升级做好，再扩展协议和主机能力。自有原生模式继续发展，两条路径共享可复用的媒体、输入和界面能力；不把原生路径的性能测试当成兼容路径的验收结果。

## 当前起点

| 方面 | UU 兼容模式 | Eclipse 原生局域网模式 |
|---|---|---|
| 连接 | 扫码账号、设备列表、官方信令 | 开发分支已支持局域网发现、手动地址、主机确认的持久配对与一键连接；保留短期邀请，加密 WebRTC 媒体，无需账号 |
| 视频 | H.264；Windows D3D11VA、Linux VA-API，软件回退 | DXGI / X11 实际采集，默认软件 H.264、Linux 实验性 VA-API，目标1–60 FPS，当前一次共享一个显示源 |
| 声音 | Opus 播放、音量与静音、短时欠载恢复 | 系统输出采集与 Opus、音频 RED 恢复，设备失效后台重试 |
| 输入 | 桌面/游戏鼠标模式、键盘捕获、前台剪贴板、多屏标签 | 主机显式允许键鼠，控制心跳与超时释放；双方许可文本剪贴板 |
| 桌面与分发 | 独立串流窗口、保留主页、HUD、混合DPI处理 | 复用主界面、观看窗口与统计；两模式随同一双平台安装包提供 |

原生图形共享、键鼠与系统声音随0.3/0.4发布；原生剪贴板、设备加载错误页、PC兼容默认签名值恢复和软件编码尺寸提示已随0.5交付。0.6完善设备收藏/最近使用、配置恢复、构建溯源和跨平台色彩解析。0.7增加Linux原生主机VA-API编码与软件回退，同时修正SRTP回绕状态及读取生命周期；硬件路径尚有CPU转换和上传。版本差异以[发布记录](releases.md)和[原生功能说明](native-streaming.md)为准。

## 第一阶段：把兼容客户端做成可靠的日常工具

近期重点是减少用户需要猜测的状态和手工操作。

- **首次使用与升级**：默认签名配置可用，账号仍需扫码；文件覆盖有误、登录过期、服务拒绝、离线和网络超时分别给出解释。设备列表先显示，缩略图异步加载。安装器保留账号、偏好与本地覆盖文件，版本和实际程序路径可查。
- **连接生命周期**：开始、取消、失败、断线、退出有清晰状态；后台任务有截止时间，迟到响应不改变新会话。关闭一个串流只影响对应设备，主窗口与其它串流继续。
- **桌面交互**：窗口移动与缩放遵循目标显示器DPI与工作区；菜单确认有反馈；绝对/相对鼠标、光标模式、全屏快捷键、前台剪贴板可预测，并在失焦和断线时释放本会话输入。
- **稳定性与观测**：音频欠载和重建可恢复；视频丢包不污染参考链，重传与关键帧请求有节奏。HUD显示实际测量值与统计定义，不能把目标帧率当作实收帧率。
- **实用工具**：在基本体验稳定之后逐项评估文件传输、终端、端口映射和远程协助。每项先验证目标主机能力和独立会话清理，不用不可操作的入口冒充功能。

## 第二阶段：Eclipse 单控端到端体验

已有原生路径证明了无第三方服务的局域网连接。下一步逐项补足日常共享所需能力：

1. 运行中切换显示源、分辨率和码率，有明确能力协商、确认与失败回退；保持主机原显示布局，虚拟屏为以后独立可选能力。
2. 将每个连接的观看、键鼠、剪贴板和声音权限明确呈现；暂停、失联和撤销权限立即生效。当前主机单控制端限制先保留。
3. 实现 Wayland 的用户授权 portal 采集与输入，正确处理用户取消、屏幕分享停止及会话恢复，不用全局提权取代桌面授权。
4. 开发分支已接入局域网发现、手动地址与持久配对，支持单独断开会话和主机撤销授权。继续完善发现诊断、地址变化、共享偏好与平台采集；保留最小邀请文件方案。

## 第三阶段：GPU 媒体管线与高画质

按实际测量决定优化顺序，分别验证每个平台后端。

- 主机已有编码抽象与实验性Linux VA-API；后续逐步接入可用的 NVENC、AMF、QSV，并减少上传；先建立H.264兼容基线，再考虑H.265与AV1。
- 控制端减少硬解后的CPU回读、颜色转换与纹理重复上传，探索GPU纹理直接呈现；记录解码到呈现的队列与时间，而非只报告解码吞吐。
- 帧节奏、显示刷新率和低延迟模式联合调度，测量帧间隔与排队分位数；垂直同步开关本身不构成无撕裂保证。
- 色彩空间、范围、色度和HDR必须端到端协商与验证；不把“能解码10位”当作完整HDR支持。
- 自适应码率和修复冗余需要网络反馈与发送端配合。现有音频RED、视频NACK/RTX不等于Sunshine/Moonlight的视频RS FEC；新增恢复机制必须协商线上格式并测量带宽和延迟代价。

## 第四阶段：自主网络与协作

局域网单控稳定后，再扩展到公网和多人场景。

- 自托管信令与设备寻址、ICE/STUN候选交换，直连失败时按配置使用TURN中继；提供明确的连接路径与诊断。
- 可信设备、短期访问许可、撤销与会话审计；无人值守与唤醒作为单独能力，不默认打开系统服务或扩大权限。
- 主机多控制端会话、一次采集/编码后分发。先实现一控多观与明确的控制权移交，再评估多人同时输入；每个连接独立授权与清理，避免一个连接释放另一个连接按住的键。
- 手柄、麦克风、环绕声和其它设备重定向按使用价值逐项推进，不以安装全局驱动作为默认前置步骤。

## 实现边界与参考方式

现有代码按GUI、账号/信令与会话、媒体、采集、输入分层，当前不存在已实现的独立 `uu-net` / `uu-host` 服务。新边界应随实际功能提取，避免为路线图预建空壳。

| 部分 | 当前落点 | 后续重点 |
|---|---|---|
| 界面与桌面 | `uu-gui` | 设备页、菜单、窗口、能力与错误反馈 |
| 会话与网络 | `uu-core` | 兼容/原生会话隔离、取消、授权、恢复和统计 |
| 媒体 | `uu-media` | 解码、音频、编码后端与GPU资源生命周期 |
| 采集与输入 | `uu-capture` / `uu-input` | 平台能力、许可、显示布局与会话输入所有权 |
| 协议与工具 | `uu-proto` / `uu-cli` | 明确版本、消息边界、可重现诊断 |
| 发布与验证 | `tools/` / GitHub Actions | 隔离测试、双平台包、版本和完整性检查 |

Sunshine、Moonlight和uu-remote-linux的固定源码参考入口见[参考索引](reference-index.md)。先研究机制与协议，再用本项目抽象实现；直接复制或链接其它实现前应核对其许可证，不能把GPL代码改标为本项目的MIT / Apache许可。协议兼容也不等于官方授权。

## 验收原则

每个功能同时交付界面反馈、异常退出路径和适用的自动/实机验证，按功能独立提交。关键测试包括：

- Windows / Linux、硬解 / 软件回退、窗口 / 全屏和混合DPI。
- 登录、设备加载、连接、取消、断线、重连、关闭主窗口与独立串流。
- 可控丢包、乱序、设备失效和权限撤销，观察错误数、最长画面间隔、队列积压与恢复。
- 旧版本互通、安装升级与清理，不读取真实工作剪贴板，不把账号数据或诊断中的个人信息发布到仓库。

测试结果记录场景与适用范围，不用某台机器的一次帧率测试承诺所有设备达到同一表现。版本只有在代码、文档、包和验证相符后才打固定标签发布。
