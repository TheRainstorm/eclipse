# 运行时插件

主程序独立提供原生 IP、自建连接服务、设备身份与授权、采集、编解码、输入所有权、音频和帧队列。主工作区和默认安装包不包含任何具体连接插件，也不要求检出插件仓库。

## 安装与启用

1. 从插件自己的 GitHub 仓库下载与当前主程序匹配的插件包。
2. 将插件包解压到软件目录，得到 `plugins/<插件 ID>/plugin.json` 和对应动态库。
3. 打开“应用设置 → 插件”，点击重新扫描，再手动启用。所有新安装、升级及缺少开关的旧配置都默认关闭。

插件提供的导航、连接服务与设置只在启用后出现。插件损坏或 SDK 不匹配时显示错误，原生连接仍可使用。停用阻止新的连接和插件入口；已有串流对象保持存活。更新或移除已经加载的动态库后，应完全退出客户端再重开。

Windows 主机统一由一个 Eclipse 服务运行，主机设置通过本地接口保存。启用插件后，“连接服务”只显示该插件对应的名称、功能和状态；没有启用插件时不显示插件区域。路径、SDK 和原始错误放在“诊断详情”中。

完整程序更新会同步当前已启用、且与包内 SDK 匹配的插件及清单声明的数据文件。程序与服务版本不一致时，在没有串流、临时屏和未完成显示器操作的空闲阶段自动继续更新；复制可执行代码仍需 Windows 系统授权，取消后保留待完成状态，不反复弹出授权。插件开关和模块选项沿用应用设置，空闲时通过原有服务接口应用，不需要再维护一个“后台启用”开关。已有串流继续使用建立连接时的状态。

## SDK 与生命周期

`uu-plugin-sdk` 是主程序随包提供的共享动态库。插件依赖引擎的通用连接服务、控制会话、输入命令和 UI 页面接口。媒体、GPU 租约、会话准入和键鼠所有权仍由同一引擎实例管理。

这是精确构建匹配的原生 SDK，不是稳定的 Rust 二进制 ABI。清单中的 API 版本、SDK 指纹、平台文件名和动态库 SHA-256 都需匹配，加载后还会校验固定 C 元数据入口，之后才调用 Rust 工厂。SDK 指纹绑定共享源码、第三方补丁、依赖锁、编译器、目标、特性和编译选项。更新主程序后应获取对应插件构建。

发现清单不执行插件代码；用户启用后才创建插件实例。成功加载的动态库保持到进程退出，避免会话、异步任务或页面还持有 vtable 时被卸载。工厂失败必须清理自身任务，不得留下引用即将卸载代码的后台工作。插件是用户主动安装的本机代码，和主程序具有相同的进程权限。

插件配置位于应用数据目录的 `plugins/<插件 ID>/`；启用开关集中保存在通用 `plugins/settings.json`。保存采用跨进程锁和单插件 CAS，避免多个窗口互相覆盖。损坏的可选配置会阻止该插件的新入口，不会覆盖原文件或阻止原生 IP 服务。

插件可以独立控制内部模块及其页面。模块策略在发布导航、连接服务和独立服务配置之前更新；关闭当前导航模块时，主程序回到设备页。插件可声明独立协议服务所需的传输，同时隐藏不适用的原生连接入口；主机只在插件已持久启用且相应服务策略允许时发布该传输，不绕过共用会话与输入权限。

## 可选 UU 插件

[UU 插件仓库](https://github.com/TheRainstorm/uu-client-plugins) 独立维护账号、注册、登录二维码、设备列表、房间信令、UU 协议和官方客户端兼容入口。主仓库不包含它的 Git 子模块或静态依赖。

UU 插件与官方中转均默认关闭。手动启用插件后，旧账号和旧路由的迁移由插件执行，并保留原件。官方客户端访问本机还需单独允许，权限不等同于原生公钥设备授权。可选中转当前仅支持 TURN/UDP；TURN/TCP 和 TURN/TLS 尚不支持。真实官方手机互通范围见插件仓库的验收说明，生成媒体测试不能替代手机实测。

启用插件后，兼容客户端和账号连接服务默认开启，实验性兼容服务器默认关闭，三者可以分别选择。顶部入口显示“UU 兼容客户端”；服务管理仅显示已开启模块的对应配置，兼容服务器权限直接显示。已有流保留准入时的权限，新连接按当前模块策略检查；主机入口及权限修改后重启共享生效。

插件维护自己的依赖锁和 CI，并在临时目录镜像引擎工作区布局构建，以保持 Cargo 的共享类型身份一致；不会改写主项目源码或加入主项目依赖。构建时按 `engine-sdk.json` 检出精确引擎提交，将插件仓库检出在引擎目录的 `plugins/` 下，再从插件工作区构建。主项目正常构建无需这个目录。插件 ZIP 在插件仓库独立发布，主程序 Release 只发布主程序完整包。拆仓与分包不改变各自及第三方的许可义务。
