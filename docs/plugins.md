# 运行时插件

主程序独立提供原生 IP、自建连接服务、设备身份与授权、采集、编解码、输入所有权、音频和帧队列。Windows / Linux 正式完整包均自带 `uu` 兼容插件与 `wallpaper-collects` 壁纸合集，默认关闭，在设置中按需启用。UU 源码仍独立维护；原生串流不依赖它。

## 安装与启用

**使用随包壁纸合集**：打开“应用设置 → 插件”，启用“壁纸合集”，再到“外观”选择对应来源，无需另外下载。

**使用随包 UU 兼容插件**：在同一页面启用 UU 插件，再在插件设置中选择需要的模块。完整包已提供匹配版本，不需要自己配对下载主程序和插件。

**单独更新或安装其它插件**：

1. 从插件自己的仓库下载与主程序 SDK 匹配的平台包。
2. 将插件包解压到 Eclipse 目录，得到 `plugins/<插件 ID>/plugin.json` 和对应动态库。不要将主程序放进插件目录，也不要额外嵌套一层解压目录。
3. 重开软件，在“应用设置 → 插件”扫描并手动启用。新发现的插件默认关闭，更新保留已有启用偏好。

插件提供的导航、连接服务与设置只在启用后出现。插件损坏或 SDK 不匹配时显示错误，原生连接仍可使用。停用阻止新的连接和插件入口；已有串流对象保持存活。更新或移除已经加载的动态库后，应完全退出客户端再重开。

Windows 主机统一由一个 Eclipse 服务运行，主机设置通过本地接口保存。启用插件后，“连接服务”只显示该插件对应的名称、功能和状态；没有启用插件时不显示插件区域。路径、SDK 和原始错误放在“诊断详情”中。

完整程序更新会同步当前已启用、且与包内 SDK 匹配的插件及清单声明的数据文件。程序与服务版本不一致时，在没有串流、临时屏和未完成显示器操作的空闲阶段自动继续更新；复制可执行代码仍需 Windows 系统授权，取消后保留待完成状态，不反复弹出授权。插件开关和模块选项沿用应用设置，空闲时通过原有服务接口应用，不需要再维护一个“后台启用”开关。已有串流继续使用建立连接时的状态。

## SDK 与生命周期

`uu-plugin-sdk` 是主程序随包提供的共享动态库。插件依赖引擎的通用连接服务、控制会话、输入命令和 UI 页面接口。媒体、GPU 租约、会话准入和键鼠所有权仍由同一引擎实例管理。

这是精确构建匹配的原生 SDK，不是稳定的 Rust 二进制 ABI。清单中的 API 版本、SDK 指纹、平台文件名和动态库 SHA-256 都需匹配，加载后还会校验固定 C 元数据入口，之后才调用 Rust 工厂。SDK 指纹绑定共享源码、第三方补丁、依赖锁、编译器、目标、特性和编译选项。更新主程序后应获取对应插件构建。

发现清单不执行插件代码；用户启用后才创建插件实例。成功加载的动态库保持到进程退出，避免会话、异步任务或页面还持有 vtable 时被卸载。工厂失败必须清理自身任务，不得留下引用即将卸载代码的后台工作。插件是用户主动安装的本机代码，和主程序具有相同的进程权限。

插件配置位于应用数据目录的 `plugins/<插件 ID>/`；启用开关集中保存在通用 `plugins/settings.json`。保存采用跨进程锁和单插件 CAS，避免多个窗口互相覆盖。损坏的可选配置会阻止该插件的新入口，不会覆盖原文件或阻止原生 IP 服务。

插件可以独立控制内部模块及其页面。模块策略在发布导航、连接服务和独立服务配置之前更新；关闭当前导航模块时，主程序回到设备页。插件可声明独立协议服务所需的传输，同时隐藏不适用的原生连接入口；主机只在插件已持久启用且相应服务策略允许时发布该传输，不绕过共用会话与输入权限。

## 可选 UU 插件

[UU 插件仓库](https://github.com/TheRainstorm/uu-client-plugins#readme) 独立维护账号、注册、登录二维码、设备列表、房间信令、UU 协议和官方客户端兼容入口。主仓库不包含它的 Git 子模块或静态依赖。下载、SDK 核对与模块使用方法见该仓库说明。

解压后的目录应为：

```text
Eclipse/
├── eclipse.exe              # Linux 为 eclipse
└── plugins/
    └── uu/
        ├── plugin.json
        └── <平台对应的插件动态库>
```

UU 插件与官方中转均默认关闭。手动启用插件后，旧账号和旧路由的迁移由插件执行，并保留原件。官方客户端访问本机还需单独允许，权限不等同于原生公钥设备授权。可选中转当前仅支持 TURN/UDP；TURN/TCP 和 TURN/TLS 尚不支持。真实官方手机互通范围见插件仓库的验收说明，生成媒体测试不能替代手机实测。

启用插件后，兼容客户端和账号连接服务默认开启，实验性兼容服务器默认关闭，三者可以分别选择。顶部入口显示“UU 兼容客户端”；服务管理仅显示已开启模块的对应配置，兼容服务器权限直接显示。已有流保留准入时的权限，新连接按当前模块策略检查；主机入口及权限修改后重启共享生效。

UU 插件维护自己的依赖锁和 CI，在临时工作区镜像引擎布局，保持 Cargo 的共享类型身份。它的独立发布按 `engine-sdk.json` 选择引擎；Eclipse 完整包则按主仓库的 `tools/release/uu-plugin.json` 锁定插件源码，并用当前主程序 SDK 构建与验证，不采用旧引擎替换主程序。插件源码不并入主工作区，构建缓存也不作为用户数据分发。

完整包的 `version.json` 记录内置插件、精确源提交、SDK 和文件摘要；`plugins/uu/build.json` 分开记录插件与主程序来源。插件更新依然要求 SDK 匹配，分仓维护不改变各自与第三方的许可义务。

## 壁纸来源

必应每日壁纸内置于软件，在外观中直接选择，不需插件。取中国区当日图片而非随机，按应用刷新策略检查；与其它来源一样共用下载、缓存及收藏。

`wallpaper-collects` 壁纸合集插件包含 Pipw 二次元和 Wallhaven 两种来源，共用一个启用开关，默认关闭。Wallhaven 的页面/分类筛选及最近100张候选去重保留；Pipw 只提供图片 API URL，下载、超时重试及缓存由主程序负责。

源码为 `extensions/wallpaper-collects/`。独立打包：

```sh
python3 tools/release/package_plugin.py --manifest extensions/wallpaper-collects/plugin.json --target x86_64-pc-windows-gnu
```

完整包已将匹配版本放入 `plugins/wallpaper-collects/`，直接在应用设置中启用即可。单独更新插件时仍需匹配主程序 SDK，并在更新后退出旧进程再重新打开。

插件扫描以 `plugin.json` 为入口：没有清单的子目录不视为已安装插件，不会因旧版本保留的目录报错；清单损坏、权限错误或启用时库文件缺失仍会显示具体错误。

### 上一张 / 下一张

F5 为下一张，F6 为上一张，F8 显示或隐藏设备列表。快捷键仅在主页聚焦且没有编辑文字时响应，右键菜单右侧会显示对应按键。

随机图片 API 在序列末尾请求新推荐；上一张回放已看到的原图，回退后下一张先沿已有历史前进。历史属于本次运行及当前来源/筛选，最多100张且压缩图总量限制64MiB，不额外保留整组解码纹理。切换来源或筛选会开始新序列，原有磁盘缓存和收藏独立保留。

必应从今日向更早日期浏览，上一张向今日返回，菜单可直接“返回今日壁纸”。近期目录通常最多约15天，以接口实际可用范围为准。回到今日会重新检查最新图片，浏览往期时自动刷新不会抢走当前位置。

Wallhaven 按所选榜单/热门/最新的接口顺序分页，已读结果在本次配置内固定，不再随机抽取。上游列表变化时，尚未读取的页面仍按其当时返回顺序接续，并过滤重复条目。
