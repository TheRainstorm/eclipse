# 配置位置与便携模式

Eclipse 默认使用用户数据目录，升级会保留已有设置。在“应用设置 → 常规 → 配置存储”可以查看实际位置，并打开配置目录或程序目录。

| 内容 | Windows 默认位置 | Linux 默认位置 |
| --- | --- | --- |
| 客户端设置、设备、配对身份、插件数据 | `%LOCALAPPDATA%\Eclipse` | `~/.local/share/eclipse` |
| 日志与运行状态 | `%LOCALAPPDATA%\Eclipse\state` | `~/.local/state/eclipse` |
| Windows 服务运行配置 | `%ProgramData%\EclipseRemoteHost\profiles\<配置标识>\data\eclipse` | 不适用 |
| Windows 服务日志与状态 | `%ProgramData%\EclipseRemoteHost\profiles\<配置标识>\state\eclipse` | 不适用 |

设置在 `gui-settings.json`；设备、画质配置和原生配对资料在 `device-trust/`；插件的配置与账号数据也位于用户数据目录。若启动环境设置了 `XDG_DATA_HOME` 或 `XDG_STATE_HOME`，用户目录分别改用该变量下的 `eclipse` 子目录。服务路径由 Windows Known Folder API 获取，不跟随这些用户环境变量。

首次使用新目录时，会将旧 `uu-remote` 用户目录中的持久配置复制到 Eclipse 目录，保留设备身份与配对，原目录保留给旧版本。已经存在的 Eclipse 配置不会被旧目录覆盖。缓存、进程锁和串流启动快照不迁移；发现链接、超过迁移上限或复制期间数据改变时，保留原数据并报告错误，不生成另一套默认身份。便携空目录不会触发这项导入。

## 独立体验首次使用

1. 将完整程序包解压到一个单独、可写的目录，保留包内所有文件，无需覆盖已有安装。
2. 在 `eclipse.exe`（Linux 为 `eclipse`）旁新建一个空文件夹，名称为 **`eclipse-data`**。
3. 启动该目录的 Eclipse。它会使用空白配置，显示首次使用教程，原用户目录和其它便携目录保持不变。

```text
Eclipse-test/
├── eclipse.exe
├── eclipse-cli.exe
├── plugins/              # 如果安装了插件
└── eclipse-data/
    ├── data/             # 设置、设备、身份、插件数据
    └── state/            # 日志与运行状态
```

空文件夹足以启用便携模式；程序不会自动导入旧设置。配置位置在进程启动时确定，修改目录后须退出这个配置的所有窗口和托盘，再重新打开。Windows 每个配置目录各有一个主窗口；使用同一配置的不同版本共用一个主窗口，使用不同便携目录的版本可以独立打开。

需要再次体验首次使用时，先退出这个配置的所有窗口和托盘，将其 `eclipse-data` 改名为备份目录，再新建空的 `eclipse-data`。恢复时换回原目录。只想重看教程，可以直接在“应用设置 → 常规”点击“打开新手教程”，无需移动配置。

## 携带现有配置与迁移

先退出使用该配置的所有主页、串流窗口和托盘，避免复制期间仍有设置更新。将原用户数据目录的**内容**复制到程序旁的 `eclipse-data/data/`。日志不是恢复配置所必需的；需要保留时，将原状态目录的内容复制到 `eclipse-data/state/`。保留原目录作为备份，首次启动便携副本后确认设备与设置。

以后退出便携副本，复制整个程序目录即可携带其中的配置与插件数据。更新程序时保留 `eclipse-data`；Windows 安装脚本更新已有便携目录时也会保留它，不自动部署系统服务。不同版本请各保留一份目录和配置副本，避免新旧版本交替写入同一份配置。

程序管理的自建连接服务令牌，在保存连接服务配置后使用相对存储位置，随配置目录迁移；从旧版本复制的配置，应在移动目录前重新保存相应连接服务。用户手动选择的外部令牌、证书或旧式连接配置文件仍使用原位置，需要一并迁移并重新选择。复制出的身份仍代表原设备；要让两台电脑成为独立设备，应让新电脑生成空白配置并重新配对。

## Windows 主机服务的范围

每份客户端配置还有独立的 `data/server/`，保存该版本的主机身份、授权、配对密码、连接入口和持久虚拟显示器设置。客户端与主机使用各自的设备身份。复制便携程序目录时，这份服务端配置也随目录迁移。

一台 Windows 电脑同时运行一个 Eclipse 主机服务。在某份配置的“服务管理”启用服务后，程序将它的服务端数据复制到 ProgramData 的受保护运行目录，并绑定此配置。运行期间由服务以所属用户的权限将变更同步回 `data/server/`；移动或备份前，请先停止这份服务并退出窗口，确保最后的变更已保存。日志、驱动安装和 Windows 服务注册属于本机，不随配置目录迁移。目录不可访问时，服务保留受保护副本并在服务日志记录未保存原因，不在旧位置重建已搬走的目录。

打开其它版本或空白便携副本，可以查看当前机器服务的运行状态。要使用它自己的主机配置，点击“切换到此配置”；有串流时须先断开。其它配置的窗口不会自动部署、启停或修改当前服务。切回原目录后，再激活原配置即可继续使用原来的主机身份、配对和设置。

首次从旧版公共服务升级普通用户配置时，保留并导入旧主机数据；空白便携配置则创建独立主机身份，不导入另一份配置。旧版服务的 `data/uu-remote` 保留给不支持独立配置的历史版本；新版本不会用它覆盖已经存在的独立主机配置。迁移到另一台电脑后，仍须在目标机启用服务和配置防火墙、虚拟显示驱动。[服务生命周期与迁移规则](windows-background-service.md)

高级启动器也可以用绝对路径环境变量 `ECLIPSE_PROFILE_DIR` 选择独立配置根目录，内部仍为 `data/` 与 `state/`。优先级为该显式变量、程序旁的 `eclipse-data`、原用户目录。该变量须由启动环境提供；常规的双击启动和系统自启动请使用程序旁的目录。无效或不可访问的独立目录会报错，不静默回退到旧用户配置。

便携目录隔离与随目录迁移的交互参考 [Moonlight 的便携版说明](https://github.com/moonlight-stream/moonlight-qt/releases)，实现独立编写；Windows 窗口按配置识别采用系统[窗口属性](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-properties)。

收藏壁纸位于当前程序目录的 `wallpapers/favorites`，可以手工加入 PNG、JPEG、WebP、BMP 或 ICO 图片。程序首次扫描发现时记为收藏时间；迁移或备份时一并保留此目录及其中清单，可保留收藏顺序和页码。缓存和生成缩略图不改变原图片。
