# 交付路线图

产品方向与技术取舍见[产品远景](vision.md)。此处仅跟踪阶段和验收；具体已发布能力以[发布说明](releases.md)为准。

| 阶段 | 当前状态 | 下一项交付与验收 |
|---|---|---|
| UU 兼容客户端插件 | 已独立分发，持续完善 | 首次使用、设备列表、错误反馈、升级、声音/输入/多屏稳定性；真实Windows与Linux路径闭环 |
| 原生局域网最小闭环 | 0.18增加连接恢复、图文剪贴板和后台服务 | 固定证书配对、加密音视频、双方许可的输入与剪贴板；真实锁屏桌面仍待验收 |
| 0.6日常体验完善 | 已发布，两端安装验证通过 | 收藏/最近使用、异常配置保护与恢复、真实构建信息、跨平台色彩和Linux窗口退出回归；完整CI与安装验证 |
| Eclipse LAN 设备发现与配对 | 0.15起已交付，0.18完善配对设置 | IPv4发现、手动地址、默认接收配对申请且需批准、固定身份与撤销授权；设备页无需第三方账号 |
| Eclipse 单控体验 | 已支持画质调整与屏幕选择，0.18完善Sway输入 | 独立真实门户验证缩放键鼠与动态输出帧率；源格式在一次授权内稳定，捕获工作量可能高于输出帧率 |
| 0.7 恢复与Linux原生硬件编码 | 已发布，完成长稳与双平台CI | SRTP回绕、读取生命周期、VA-API选择/回退、AltGr、共享地址与私有诊断；完整包交付 |
| 0.8 Linux硬件互通与观测 | 已发布，双平台CI及原包核验通过 | 有效NACK补包与重放记录、BGRA转换加速、SPS约束与零重排、尾部填充、停图FPS归零及调试不再隐式保存画面 |
| 0.9 客户端低延迟呈现 | 已发布，双平台CI及硬解重复对照通过 | GPU平面转换、Windows读回缓冲复用、低延迟接口、500ms统计；保留VSync，记录解码与渲染的真实范围 |
| GPU媒体管线 | Linux VA-API、Windows MFT、Intel VPL与原生AMD AMF | 三格式GPU输入/硬解和AMF准备加首帧原生对照通过；继续测量真实桌面端到端表现，原生NVENC尚未实现 |
| 高画质与恢复 | H.265 / AV1、CBR / VBR、0.18按需关键帧与有界XOR FEC | 已验证单丢恢复和参考链保留；HDR、发送端包节奏与跨设备网络调优仍待实现或验收 |
| 自托管公网连接 | 开发分支已接入自有信令、STUN、逐设备授权和路径详情 | 不同 NAT 的实际直连验收；STUN 无法保证任意网络打洞，自有 TURN 尚未实现 |
| 多控制端与扩展设备 | 开发分支已接入最多四会话、独占输入交接、手柄与运动传感器 | 实体手柄、UHID / ViGEmBus 驱动与实际多设备验收；UU 并发还受服务侧策略限制 |
| Windows后台共享 | 0.18实现受保护SCM服务和控制台媒体进程 | System生成媒体、安装回滚与崩溃恢复通过；所属用户登录后的真实Win+L画面、目标设备驱动仍待验收 |
| 官方手机客户端兼容 | 完成0.19要求的可行性分析 | 当前原生server不能直接连接官方手机；需另行实现协议、准入和能力适配，见[兼容分析](official-mobile-client-feasibility.md) |

先完成当前阶段的退出清理、错误提示、测试与安装交付，再扩展下一阶段。暂不为未实现功能显示可用入口，不将实验路径标成完整服务端；原生模式也不代表已兼容Sunshine / GameStream。

各项交付以对应版本的发布说明及实际安装包为准。生成媒体、隔离门户与虚拟手柄测试用于验证协议和生命周期，不等同于真实桌面、目标 GPU、物理手柄或跨 NAT 验收；各功能文档记录其具体边界。
