# Windows 服务与锁屏串流

Windows 的主机状态由一个 Eclipse 服务持有。同一配置的主窗口、“服务管理”、托盘和独立管理窗口操作当前选中的主机配置、配对记录、会话权限和虚拟显示器状态；获准管理的远端连接只能读取公开状态。每份程序数据目录保留独立的主机配置；不同版本一次只激活一个服务端，切换须在没有串流时明确执行，其它配置的窗口不能自动接管或修改它。关闭 GUI 或退出托盘不停止服务。绿色 Server 图标表示服务已有就绪的连接入口；黄色表示后台服务未启动、仍在准备或暂时无法确认就绪。

首次选择“启用服务”时，应用校验完整程序包并请求 Windows 管理员授权，注册开机自动启动的服务。首次从历史公共服务升级普通配置时保留原来的主机身份、配对密码、授权记录和持久虚拟显示器；全新独立配置使用新的主机身份及自己的共享设置，自建入口的凭据复制到服务的受保护目录。以后部署程序包只更新代码和运行库，保留服务原有配置和配对，不再用 GUI 用户目录中的旧主机设置覆盖它们。客户端设备收藏、预览和画质偏好仍属于客户端。

完整安装包更新会一并更新 Eclipse 服务和当前已启用的匹配插件。同一配置的启动器发现程序与实际服务构建不一致时，也会在空闲阶段自动继续更新；Windows 可能请求系统授权。正在串流、手动临时屏尚未关闭，或显示器操作尚未完成时等待，不自动中断它们。取消或失败时明确保留“更新尚未完成”的状态，并可手动重试。版本详情保留 GUI、实际服务进程和已安装程序的构建编号，供诊断核对；不能读取时明确显示未知。安装器先核验和准备新版本，再切换服务，普通程序安装失败会尝试恢复原安装记录、服务状态和本次防火墙变更；插件同步失败单独报告，不冒充全部更新成功。

多个窗口或进程遇到同一次更新时，会等待已有操作并重新检查结果，已完成的目标不重复安装。自动更新只用时间顺序明确的较新完整包替换较旧完整包；版本不同本身不代表需要自动替换。需要体验旧版本时仍可手动明确部署。更新页只显示一个当前阶段进度。更新规则随程序生效，已经运行的旧程序需要退出并重开，才能使用这些规则。

服务运行期间直接在 GUI 修改配置，由服务校验版本并保存。其它窗口已经修改同一配置时，保存会报告冲突并保留当前草稿，需要重新读取后再决定如何修改。

“连接服务”中的自建 WSS 服务器也由服务保存。在“自建服务器”卡片粘贴接入码即可添加，码内含地址、组凭据和必要证书；GUI 不提交服务端文件路径，也不读取服务的令牌文件。每台服务器下展示自己的在线设备。服务器别名属于本机界面偏好，与接入码组名及凭据分开；“启用”开关控制本机上线，关闭后仍可连接其它设备。更换组凭据后，已有连接继续使用原凭据版本，服务入口在空闲时应用新配置。

| 变更 | 生效规则 |
| --- | --- |
| 虚拟显示器创建上限 | 保存后立即限制后续创建；降低上限不关闭已有显示器。 |
| 显示器的临时或持久状态 | 管理操作成功后立即生效；持久配置由服务保存。 |
| 采集、编码、声音及控制默认值 | 新连接使用新设置，已有串流继续使用建立连接时的设置。 |
| 配对密码、公钥授权 | 由服务立即更新。修改已有设备授权或撤权时，旧连接结束并释放输入。 |
| 当前会话的键盘、鼠标、手柄、显示器和画质 | 由服务端“会话”面板立即修改当前媒体；缩减输入会释放已持有输入，不写回设备长期授权。 |
| 主机名称、监听端口、连接入口 | 保存后提示待重启；选择“保存并重启服务”后应用；存在串流或连接数未知时在当前页面确认，零会话直接执行。 |

普通 GUI 不再直接打开服务的私钥或受保护配置文件。安装时仅向指定的 Windows 用户授予服务启停和查询权限，日常修改配置和管理虚拟显示器不需要再次打开管理员 GUI。部署可执行程序、导入插件代码或安装驱动仍使用 Windows 系统授权；组织策略的拒绝权限不会被绕过。

服务端会话面板是连接控制的唯一写入入口。它按会话分别显示键盘、鼠标、手柄开关、当前显示器、帧率和码率；设备长期授权是这些开关的上限。远端控制端只能读取主机公开状态，不能提交会话权限、画质、显示器、断开会话或主机配置修改。设备授权变化仍会结束对应设备的旧会话；会话级缩减只影响当前连接，可在上限内恢复。

服务管理与托盘的虚拟显示器入口始终指向这个服务。临时屏随所属串流断开而回收；持久屏保留，服务开机启动后按保存设置恢复。服务启动本身不静默安装缺失驱动；驱动卸载或记录损坏时保留原始记录并报告未完成。首次驱动安装和后续准备规则见[虚拟显示器](virtual-displays.md)。

插件仍默认关闭。只有用户已经启用的插件会参与同步，账号和配置文件的复制范围受匹配插件清单中的 `data_files` 白名单限制。没有启用插件时，“连接服务”没有空插件栏；启用后显示相应插件卡片，原始诊断收在折叠详情中。插件功能与开关在应用设置中管理，服务空闲时应用变更。

服务随 Windows 启动，在安装时选定的活动物理控制台运行共享。系统明确报告没有登录用户令牌且控制台用户名为空时，可在登录屏启动；查询失败或用户切换中的不一致状态不会作为未登录放行。指定用户登录后和 Win+L 锁屏期间继续共享；换到其它用户或控制台会话改变时，旧媒体进程退出，原串流可能断开。当前方案不接管任意 RDP 会话。休眠、断电或没有有效显示输出时无法串流。

Windows 服务进程位于 Session 0，负责开机生命周期、受保护程序和本地管理入口；它监督活动控制台中的无界面 LocalSystem 媒体进程。两者属于同一个主机服务，不各自持有用户可选的配置。采集、输入线程跟随当前输入桌面，DXGI 失效时清除缓存并重建采集。远端仍须完成设备认证，并输入自己的 Windows 登录凭据；服务不会自动解锁系统，SendInput 不能生成 Ctrl+Alt+Delete 安全注意序列。登录屏、锁屏、冷启动和跨桌面恢复仍需在实际机器验收，状态测试不能代替这些验证。

Windows 同一物理输出只能被一个 DXGI duplication 持有。后台媒体进程因此把同一屏幕的采集源登记为进程级共享所有者，多个客户端从各自的最新帧槽读取同一源画面，再分别编码和传输。关闭一个客户端只取消其订阅；最后一个订阅退出后才释放采集。不同显示器仍各自拥有采集所有者。混合 HDR/SDR 会话加入已有物理源时沿用该源当前打开的采集模式，不会为后加入会话重新 duplication 同一输出。

服务名为 `EclipseRemoteHost`。程序位于 Windows Program Files 的同名目录，配置与日志位于 ProgramData 的同名目录，实际路径由 Windows Known Folder API 获取。每份配置的日志为 `profiles/<配置标识>/state/eclipse/log/service.log`，约 4 MiB 后在下次启动时轮换。服务运行数据保存在受保护的 `profiles/<配置标识>/data/eclipse`，变更同步回所属程序配置的 `data/server/`；复制配置前先停止服务并退出窗口。历史公共服务目录保留给旧版本。移除服务注册保留配置，以便重新安装；彻底删除需在停止服务后由管理员移除对应目录。

管理员也可以从完整程序包目录运行：

```powershell
.\eclipse-cli.exe service install
.\eclipse-cli.exe service status --json
.\eclipse-cli.exe service start
.\eclipse-cli.exe service stop
.\eclipse-cli.exe service restart
.\eclipse-cli.exe service import-plugins
.\eclipse-cli.exe service remove
```

默认 TCP 48998 用于设备检查和授权；串流 TCP TLS 握手与 UDP 媒体使用 `49000–49009` 端口池。服务安装和共享入口启动检查实际受保护程序的防火墙规则，缺失时仅创建 Domain、Private 的本程序入站规则。已有规则不自动放宽或启用，组织 Block 不覆盖。服务管理可在不中断串流的情况下检查或修复缺失规则；规则存在不证明端口可达或画面已经接收。

升级仅迁移 PersistentStore 中精确绑定旧程序路径的规则，只改变 Program，保留其它过滤条件；旧新路径都有规则时报告冲突。失败补偿仅接受本次完整 postimage，不覆盖管理员并发修改，不导入全局快照，也不保证断电原子性。

本地管理使用拒绝远程客户端的命名管道。外部入口只给 System、管理员和安装时指定的用户；普通用户只获管道数据读写权限，不获创建服务端实例的权限。GUI 在发送配对码或密码前，用 SCM 的实际服务 PID 核对管道服务端。内部媒体通道保持管理员与 System 边界，接收的操作为有大小限制的类型化请求，不接受任意命令、程序路径或私钥导出。已提交的显示器操作即使关闭 GUI 也继续收尾，回执丢失时先检查同一服务状态，不自动重复创建。

SCM 异常恢复的等待时间依次为 1、5、15 秒；正常停止不触发恢复。服务通过私有 Job 对象管理自有媒体进程，停止先请求正常收尾，超时只终止该服务拥有的进程。

平台约束参见微软的[服务与交互界面](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services)、[DXGI 桌面复制](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutput1-duplicateoutput)、[命名管道权限](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)和[服务访问权限](https://learn.microsoft.com/en-us/windows/win32/services/service-security-and-access-rights)。服务和桌面生命周期设计参考 Sunshine，代码独立实现。

托盘右键的“悬浮会话中心”可独立于主窗口管理当前连接。共享游戏厅、本机键鼠优先与手动暂停的行为见[会话中心与共享游戏厅](host-session-control.md)。
