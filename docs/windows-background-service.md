# Windows 后台服务与锁屏串流

服务设置和“管理后台服务”会显示后台的实际运行版本、进程 ID，以及当前普通程序版本。已安装程序与正在运行的后台不一致时分别显示；无法读取运行进程时明确显示“无法读取”，不会用已安装版本代替。普通窗口可能无权读取 System 服务进程的程序路径，此时打开“管理后台服务”，确认管理员提示后查询；“无法读取”本身不表示后台停止或版本过旧。也可以在管理员 PowerShell 中运行 `eclipse-cli.exe service status`，或使用 `eclipse-cli.exe service status --json` 获取结构化状态。构建哈希可与普通程序“关于”中的构建编号核对。

普通程序、受保护后台程序与后台插件分别维护。解压或同步普通程序不会替换正在运行的后台，主窗口的插件和账号变化也不会自动导入后台。

| 按钮 | 作用 | 对现有后台串流的影响 |
| --- | --- | --- |
| 管理后台服务 | 打开管理员管理窗口，查看状态、配对、共享设置和虚拟显示器；打开或关闭窗口不更新程序、不重启服务。 | 仅打开窗口不会断流；在窗口中另行选择停止或重启会断流。 |
| 更新后台程序 | 校验当前目录完整主程序包，安装受保护程序和运行库并重新启动后台；已有后台保留自己的配置和配对身份。此操作不导入插件。 | 会断流；主窗口正在运行的前台共享也会先停止。 |
| 同步插件并重启后台服务 | 将当前目录中已启用的插件程序，以及当前用户的插件开关、选项和插件声明的数据文件导入后台。声明的数据可能包含登录账号。 | 后台原本运行时会停止并重新启动，导致断流；原本停止时保持停止。 |

后台程序版本落后时，先用“更新后台程序”。需要在后台使用当前用户的插件时，再用“同步插件并重启后台服务”；插件 SDK 必须与后台程序精确匹配。只使用原生共享时不需要同步插件。插件同步会覆盖对应的后台插件配置或账号状态，并非只复制 DLL。

在主窗口的服务设置中选择“安装并启动后台服务”，确认 Windows 管理员提示。首次安装使用当前已保存的共享设置、设备身份、配对密码和授权记录；已启用的自建入口凭据会复制到服务的受保护目录。独立插件及其登录状态需另行显式同步。客户端收藏、预览和串流偏好继续保留在用户配置中。

后台服务随 Windows 启动，等待安装时选定的控制台用户登录。管理员提示中使用另一位管理员的凭据时，共享用户仍是当前控制台用户。在同一用户按 Win+L 锁屏后保持运行；注销或切换到其他 Windows 用户时停止该用户的媒体进程，该用户重新登录后恢复。需要有效的物理或虚拟显示输出，系统休眠、关机、断电或未登录状态不能开始串流。当前实现针对控制台会话，不接管任意 RDP 会话。

普通窗口共享仍受当前用户的桌面权限限制。Windows 的安全桌面采集要求 LocalSystem 身份；后台服务在目标控制台会话中启动无界面的 System 媒体进程。采集和输入工作线程跟随当前输入桌面，桌面切换或 DXGI 失效时清除缓存并重建采集，恢复后发送关键帧。服务不会自动解锁 Windows；用户仍需在远端输入自己的 Windows 登录凭据。通过 SendInput 不能生成安全注意序列 Ctrl+Alt+Delete。

“管理后台服务”打开独立的管理员窗口，可以批准新设备配对、设置密码和授权公钥、调整设备权限、查看与断开连接，以及编辑共享设置。配置可在串流中保存，选择下次启动生效，或保存后重启再连接。关闭管理窗口后，后台服务继续运行。拥有“管理服务和连接权限”的远端设备也可通过原生串流窗口管理服务，沿用相同的保存与权限规则。

管理入口直接使用当前主窗口程序，不依赖同目录旧版 `uu.exe`。安装、更新和同步账号需要完整且版本一致的 Windows 安装包；只替换其中一个程序时会在管理员提示前给出缺失或校验失败的文件名。请将整个安装包解压到同一目录，保留 `version.json` 和运行库。管理员操作或管理窗口启动失败时会弹窗显示具体原因。

安装或更新后台程序成功后，前台共享的自动启动选项关闭。前台用户配置和后台服务配置分别保存，后续后台设置应在后台管理窗口或具有管理权限的远端客户端中修改。主窗口中的插件重新登录、登出或修改选项后，需显式同步才会影响后台。安装新版普通程序后，使用“更新后台程序”更新受保护的后台程序，保留后台配置和配对身份。安装器先准备完整的新版本，再切换服务；切换或启动失败时恢复原安装记录和服务状态，并报告恢复结果。

也可以在安装包目录使用管理员 PowerShell：

```powershell
.\eclipse-cli.exe service install --open-manager
.\eclipse-cli.exe service status
.\eclipse-cli.exe service manage
.\eclipse-cli.exe service stop
.\eclipse-cli.exe service start
.\eclipse-cli.exe service restart
.\eclipse-cli.exe service import-plugins
.\eclipse-cli.exe service remove
```

服务名为 `EclipseRemoteHost`。程序安装在 Windows Program Files 的同名目录，配置和服务日志保存在 ProgramData 的同名目录；实际位置通过 Windows Known Folder API 获取。日志位于服务配置的 `state/uu-remote/log/service.log`，达到约 4 MiB 后在新进程启动时轮换。移除服务注册会保留受保护配置，便于重新安装；彻底移除时，在服务停止后由管理员删除对应目录。

排查连接时，应检查正在运行的后台 `eclipse-cli.exe` 的防火墙规则。默认 TCP 48998 用于设备检查和授权，每次串流还会使用动态 TCP 端口完成 TLS 会话握手，以及动态 UDP 媒体端口。仅允许 TCP 48998 可能导致设备检查成功后出现 `native pairing timed out`。可按实际后台程序路径允许所需网络配置文件中的 TCP/UDP 入站；更新后台版本后也要核对规则是否仍匹配当前路径，应用不会自动修改防火墙。

服务日志记录会话等待的地址、设备连接失败原因，以及媒体会话结束时的会话编号、阶段和错误链。若记录停留在 `native host waiting for an invited controller`，随后出现 `native invitation expired before a controller paired`，应检查该行动态 TCP 端口是否可达。这些日志不记录邀请 token、配对码或剪贴板正文。

安装器验证包内程序哈希，拒绝重解析点及普通用户可修改的服务目录。媒体进程由服务私有 Job 对象管理，停止时先请求正常退出，超过期限仅终止该服务拥有的进程。管理通道仅向本地管理员与 System 开放，拒绝远程命名管道连接；客户端还会核验服务器的 System 身份及受保护程序位置。新设备仍需完成配对，后台服务不自动批准请求。

SCM 在服务异常退出后自动重启，连续失败时等待时间依次为 1、5、15 秒；正常停止服务不会触发这项恢复。媒体子进程由服务单独监督，退出后重新等待所属控制台会话并启动。

实现参考了 Sunshine 的服务与桌面生命周期设计，代码独立实现。Windows 平台约束见 [DuplicateOutput](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutput1-duplicateoutput)、[OpenInputDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openinputdesktop) 和 [SetThreadDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddesktop)。
