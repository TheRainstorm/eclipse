# Eclipse 局域网设备与配对

本文对应当前开发分支；v0.9.0 及更早的发布包仍使用[邀请文件](native-streaming.md)。原生模式使用本项目自己的主机、身份与信令，不需要兼容服务的账号或签名凭据，也不兼容 Sunshine / GameStream。

## 连接两台电脑

1. 在目标电脑启动图形客户端，选择“共享本机”。选择屏幕、帧率、码率及是否共享键鼠和系统声音，然后点击“启用共享”。共享期间需要保留软件运行。
2. 在主机点击“允许新设备配对”，开启两分钟配对窗口。开启共享本身不会允许新设备取得授权。
3. 控制端启动后默认进入“Eclipse 局域网”，自动查找设备。也可以通过“添加设备”输入 IP 或主机名；非默认端口使用 `主机:端口`，IPv6 使用 `[地址]:端口`。离线设备地址也可以保存。
4. 点击“配对”。控制端显示八位配对码，在目标电脑输入相同号码后允许连接。不要批准来自不认识设备的请求。
5. 配对成功后自动打开独立串流窗口。以后点击“连接”即可，主机无需再次开启配对窗口。设备主页继续保留。

两台设备必须能直接通过局域网互通。默认 TCP 47998 用于设备检查、配对与连接请求，UDP 47999 用于 IPv4 局域网发现；每次媒体会话另外使用临时端口。广播可能被访客网络、VLAN 或防火墙隔离，此时可尝试手动地址；输入地址不能绕过网络隔离。软件不会自动修改防火墙。

目前主机一次只接受一个串流会话，共享选定的一个显示源。运行中切屏、画质协商和无人值守系统服务尚未实现。Windows 使用当前交互会话的 DXGI 采集；Linux 主机使用 X11，Wayland 客户端可连接其它主机，但 Wayland 本机共享尚未接入 portal。共享不更改显示器布局。

原生串流沿用 HUD、音量、静音、全屏和退出快捷键。键鼠控制受主机许可和控制端会话权限共同限制。新局域网共享窗口尚未提供剪贴板授权，默认不共享剪贴板；旧邀请通路的双方许可剪贴板独立保留。

## 设备身份与退出

局域网广播只携带设备名称、标识、端口和公有证书指纹，发现设备不代表信任设备。首次配对码由本次 TLS 连接导出，两端独立计算；主机核对后才颁发随机的客户端专属授权。配对码不是长期密码，授权凭据不会进入广播或子窗口命令行。

主机证书和授权记录保存在用户配置目录的 `native-lan/` 中；控制端的 `paired-devices.json` 保存固定证书及授权凭据。文件属于私人配置，不应提交到仓库或附在 issue 中。Unix 文件仅当前用户可读写；尚未集成系统凭据保险库。

同一设备换 IP 时，控制端先验证固定证书，再保存新的地址。证书变化会阻止连接并提示核实；确认重新安装等原因后，可忘记旧配对再重新配对。损坏的配置会明确报错并保留原件。

主机在“共享本机”中可撤销某个设备的授权，撤销也会停止该设备当前串流。控制端“忘记配对”只移除本地记录，主机授权应在主机侧撤销。停止共享或正常退出主机软件会停止监听、当前串流和待确认配对；下次手动启用共享仍可使用既有配对。

## 实现与验证

`native_discovery` 负责有界 UDP 查询与地址解析；`native_lan_store` 保存持久身份及可撤销的独立授权；`native_lan` 提供 TLS 1.3 连接代理。每次通过已认证连接生成新的短期原生串流能力，复用现有 WebRTC DTLS-SRTP 媒体与恢复策略。

回环测试使用生成画面，覆盖主机确认、拒绝、授权撤销、证书变化、服务重启、连接数量限制、等待配对超过普通 RPC 超时及真实视频解码。图形设备页测试覆盖不登录账号的地址添加、配对码核对、持久保存和解码闭环：

```sh
cargo test -p uu-core -p uu-gui --features vaapi --locked native_lan
```

这些检查不等同于跨平台实机性能验收。硬件解码、声音、输入与网络体验仍须按实际平台验证。

## 前台服务与命令行诊断（开发分支）

`uu lan` 提供与图形端共用的设备存储和协议。`discover` 查询广播，`inspect 主机[:端口]` 仅检查公开信息，`devices` 列出本机保存的配对，`pair 主机[:端口]` 显示待主机核对的配对码。`probe 设备ID --frames 120` 使用已保存授权请求一次串流并解码，不播放声音、不发送键鼠，也不保存画面。

可以在两个终端验证生成画面，不读取桌面：

```sh
# 主机终端：默认仅监听回环地址，按输出提示输入 pair 开放配对
uu lan host --synthetic --bind 127.0.0.1:47998
# 控制端终端：显示八位码后，在主机输入 code 后跟这个号码
uu lan pair 127.0.0.1
uu lan devices
uu lan probe <设备ID> --frames 120
```

主机终端输入 `stop`、关闭 stdin 或按 Ctrl+C 都会结束前台共享。`close-pairing` 关闭新配对窗口，`deny` 拒绝当前请求，`revoke 客户端ID` 撤销授权。没有自动批准参数，不需要在启动参数中传递令牌。

跨电脑需要通过 `--bind` 明确选择主机监听地址；只有显式设置 `--discovery-bind 本机地址:47999` 才开启 CLI 广播应答。去掉 `--synthetic` 才会采集当前会话的真实屏幕，`--monitor` 选择显示源，`--allow-input` 和 `--audio` 分别允许键鼠与系统声音。生成画面与桌面输入参数不能同时启用。CLI 主机默认软件编码，可显式指定 `--encoder auto`。

独立进程回归使用临时私有配置和自建回环服务，覆盖错误配对码、保存授权、解码、重启后复连、撤销和关闭：

```sh
python3 tools/native/lan_smoke.py --exe target/release/uu --output artifacts/lan-smoke
```

输出目录必须是新目录。结果只保存生成视频的接收统计，不保存私钥、令牌或配对码。
