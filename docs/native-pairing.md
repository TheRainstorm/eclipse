# 原生模式配对基础

这是[原生局域网观看](native-streaming.md)使用的认证组件。原生主机与观看窗口现已接入这条配对通路；兼容客户端的登录流程保持独立。

每次原生主机会话生成自己的 TLS 证书与256位随机访问凭据，不使用任何第三方生产密钥。主机证书、连接地址、访问凭据和有效期放入用户主动传递的 `.eclipse-invite.json` 文件。该文件等同访问许可，只分享给希望授权的控制端；不要上传、放入命令参数或粘贴到日志。

控制端只信任邀请中的主机证书。TLS1.3握手完成后，在加密通道内验证访问凭据；凭据比较使用常量时间实现。证书不匹配、凭据错误、邀请过期或握手超时均拒绝连接。主机必须在认证成功后才启动桌面采集或允许输入。媒体阶段还需要通过这个已认证通道交换 WebRTC SDP，再使用 DTLS-SRTP。

邀请有效期由主机设置，最长1小时。有效期内持有同一邀请的客户端具有同等配对能力，它不是单次验证码；请勿分享到公共位置。停止主机会话会丢弃该次证书私钥与访问凭据，新会话需要新邀请。该基础组件不实现无人值守设备身份、长期配对记录、互联网服务发现或密码找回。

邀请文件必须显式保存为新文件，不覆盖已有文件。Unix 创建权限为600，并拒绝加载组／其它用户可读的邀请；Windows 应保存到当前用户的私有目录，访问控制由该目录的 ACL 决定。仓库忽略这类文件，发布守卫也会拒绝源码或安装包中的邀请文件。
