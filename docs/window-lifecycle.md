# 串流会话与窗口生命周期

串流连接、解码器和授权属于会话；原生窗口只承载会话。拆窗与合并移动完整的会话对象，不重建连接。每个会话拥有独立的 `window_context::Context` 路由，其异步克隆共享当前绑定，而不是保存创建回调时的窗口 ID。

路由具有三个状态：

| 状态 | 行为 |
| --- | --- |
| Bound | 重绘、视频通知和窗口命令交给当前承载窗 |
| Transferring | 已在旧窗释放输入，等待目的窗绑定；迟到通知不再唤醒旧窗 |
| Retired | 会话已最终销毁；所有克隆均停止通知，不能再次绑定 |

移动会话前先按原规则释放按住的输入和指针捕获，再挂起路由。目的窗完成原生平台绑定后恢复同一路由。目的窗尚未建立时，会话仍由目的容器持有并保持 Transferring；取消迁移可重新绑定原窗，最终销毁则退休路由。空源窗口的析构不拥有已移出的会话，不能退休其路由；另一个会话也有独立路由。

路由互斥锁只用于读取和更新状态，不跨入 egui。egui 的重绘通知会同步调用后端回调，因此不能在路由锁内调用它。迁移前已经读取旧 ID 的通知仍可能在迁移后进入 egui；这由后端的窗口声明边界处理。

egui 0.29 收到未知 ID 的重绘或窗口命令时，会建立默认 `Root` 类型的占位条目。占位条目不是创建原生窗口的声明：只有 `ViewportId::ROOT` 能使用 `Root` 类型，子窗必须由 `show_viewport_deferred` 或 `show_viewport_immediate` 显式声明。Glow 和 Wgpu 在处理 viewport 输出时共用这一校验，防止迟到通知创建空白原生子窗。已声明窗口的父帧回收规则保持不变。

定向检查覆盖根窗与子窗、两个子窗之间的移动、取消迁移、最终销毁、不同会话的所有权和同步回调。`viewport_lifecycle_probe` 在 launcher 独占认证的 Xvfb 中创建生成窗口，并持续发送异步光标和视频通知，同时注入一次迁移期间的迟到旧 ID；不连接真实主机、不注入用户输入、不采集桌面。它补充状态测试，不能替代用户实际桌面的拆并操作验收。
