# 虚拟显示器（实验性）

Windows 原生共享支持创建临时和持久虚拟显示器。Eclipse 只管理自己创建的设备；物理屏、其它程序的 MttVDD、Zako 等显示器仍列在串流菜单的“已有显示器”，不纳入 Eclipse 的创建数量或删除操作。

## 创建与删除

“服务管理 → 虚拟显示器”和托盘显示入口操作当前激活配置的主机服务。服务未启用或属于另一份配置时，先在服务管理中启用或切换；日常创建、编辑和删除由服务执行，不需要管理员 GUI。关闭管理弹窗不会取消已经提交的操作，关闭 GUI 不停止主机服务。

创建一块屏幕才向 Windows 添加一块；删除后移除该屏幕的设备，不保留预建的断开目标。创建上限只限制后续分配数量，不按上限预装显示器。默认上限 1，范围 0–16；0 禁止新建，降低上限保留已创建的屏幕和持久意图，用户可逐个删除。其它程序的显示器不计入上限。

每块已创建屏幕占一行，提供名称、分辨率、刷新率、HDR、持久开关以及保存、删除操作。新屏幕默认使用 Athena、Apollo、Artemis 等不同名字。名称仅用于区分，不作为采集或设备删除的身份。只改名称立即生效；修改正在使用的屏幕规格需先结束该主机的串流。

“创建设置”始终展开，决定下一块屏幕的规格与生命周期。“刷新”只读取状态。成功提示两秒后消失，等待结果的提示保留；失败可复制诊断详情。请求结果未知时先检查同一服务，不自动重发创建。

## 驱动准备与升级

主程序不附带驱动。首次明确新建时，获授权的服务检查并下载固定版本的原始签名包，验证完整摘要与系统签名策略，再安装本次新设备。驱动适配器尚未出现在设备管理器，不等于准备失败：没有已创建屏幕时，Eclipse 不保留空适配器。

“检查驱动准备”校验准备好的签名文件，缺失时下载并准备；此操作不创建显示器，也不恢复历史桌面布局。下载优先使用官方 Release 地址，失败时尝试同一固定资产的官方 API；两者必须匹配相同 SHA-256。不导入测试证书、不关闭签名检查、不修改其它驱动。

每块屏幕使用独立的原始 Mtt PnP 设备，并在首次启动前设置不同的 UMDF 设备组，隔离驱动进程中的状态。创建与删除只处理这块设备，不使用驱动的全局重载或整批销毁命令。各设备读取固定的一屏配置，创建上限不改变驱动屏幕数量。 Windows 热插拔按当前连接组合保存扩展桌面关系，因此明确创建后会保存刚刚应用的当前组合，避免删除一块时把兄弟屏恢复为停用。提交前后核对全部活动输出；不读取历史布局来覆盖现在的桌面。

旧版 Eclipse 留下的预留池仅在能核对自身首次安装记录、原签名驱动、配置和精确设备身份时迁移；其它进程仍持有或使用的屏幕会保留。旧池内未使用的目标可以随自有旧适配器一并移除，持久屏按保存规格在新路径恢复。未知来源的 Mtt 安装不会凭名称自动卸载。升级后应先更新实际主机服务；只更新客户端不会改变旧服务的预留池行为。

## 生命周期与恢复

临时屏属于创建它的连接，断开后删除；手动创建的临时屏随主机服务退出清理。持久屏在创建成功前保存名称和规格，连接结束后继续由服务持有。停止服务时移除自有设备并保留持久配置，下一次启动重新创建。复制版本目录可保留配置，机器上的设备身份和驱动恢复记录不随目录复制。

管理器持续持有每块目标的跨进程租约。设备的配置标识、逻辑屏幕 ID、随机所有权标记和精确 PnP 实例记录在本机受保护目录，创建提交前先记日志。失败先清理本次设备；无法确认清理时保留记录并停止追加设备。服务重启后只恢复同一配置的记录，不能凭相同显示名称删除设备，也不回放旧的全局显示布局。

原来的物理屏和其它程序的虚拟屏保持独立。删除自有屏幕后，Windows 可能调整自有兄弟屏的位置；程序不会为恢复旧坐标而重新创建已删除的显示器。机器重启、驱动安装、HDR 和真实多屏串流仍须在对应 Windows 环境验收；状态模拟或类型检查不等同于实机验证。

## 串流中创建屏幕

两端更新后，源机还需授予该设备“管理服务和连接”权限。显示器标签旁的“+”优先打开尚未访问的活动屏；没有可用屏幕时，按默认规格新建临时屏。右键“+”可以选择已有显示器、临时或持久创建，以及当前或独立窗口。新标签确认显示源和画面后开放输入，原有连接继续运行。

每个临时屏属于自己的完整连接，移窗、合并和媒体重新协商保留租约。标签右键“断开此会话”只结束该标签并回收其临时屏；电脑名菜单或退出快捷键结束当前窗口此设备的全部连接。失败页的关闭操作也只影响当前标签。窗口右上角 X 按整窗范围关闭。[多显示器独立窗口](multiple-displays.md)

## 规格与活动屏幕

“软件设置 → 虚拟显示器规格”提供 1080p60、1440p60、4K60 初始规格，可添加名称、分辨率、含小数的刷新率及 HDR，并选择默认规格。更改预设仅影响之后创建的屏幕；规格保存在本机配置，在串流窗口之间同步。

同一输出只改变位置或主屏时，Eclipse 重建失效的采集并更新输入坐标；等待期间不使用旧画面或旧坐标，保留连接和租约。分辨率、旋转或 HDR 变化涉及采集模式，仍需要重新协商，不能保证原串流持续。需要其它规格时，可以通过“+”新建对应屏幕。
