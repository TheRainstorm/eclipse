# 虚拟显示器（实验性）

Windows 原生共享支持管理虚拟显示器。主程序不默认携带驱动；可使用已有的 MttVDD 或 Zako 驱动，也可在源机管理窗口显式安装受支持的签名驱动。其它虚拟显示驱动不会被自动接管。

## 源机管理

源机运行 Eclipse 前台共享或已安装的后台服务时，可从系统托盘右键打开“管理虚拟显示器”。后台服务通过本地管理员通道管理，需要在管理员管理窗口中操作；普通目录中的 GUI 更新不会替换后台进程。

当前托盘入口在前台共享运行或仍持有前台虚拟屏时，优先打开前台共享进程的管理页；后台服务同时运行也不会改变这个选择。管理独立后台的虚拟屏时，从“管理后台服务”打开管理员窗口，再点击“虚拟显示器”。普通窗口没有管理员权限时，后台管理请求会被拒绝；这与驱动是否有空闲槽位是两个独立条件。

管理窗口可指定分辨率、刷新率及 HDR，新建或移除手动虚拟屏。手动屏由实际共享进程拥有，保留到主动移除或该进程正常退出。前台共享与后台服务各自管理自己的租约。

创建需要一个已连接、未加入 Windows 桌面布局的空闲虚拟屏槽位。如果已有虚拟屏正在输出，可在源机列表中明确选择“提供为空闲虚拟屏”，确认后只停用所选目标，再用它创建临时屏。最后一个活动桌面输出不能提供为空闲槽位。已安装但没有连接目标的驱动，需要先在原厂管理工具或 Windows 设备管理器中准备；应用不会自行修改驱动的全局屏幕数量或重载已有适配器。

“新建”目前表示激活这样的空闲目标，不会请求驱动增加新的目标。驱动已安装、但全部目标都在输出时，仍会提示没有空闲槽位；更新后台或同步插件不能增加槽位。“提供为空闲虚拟屏”会断开那块已有虚拟屏的桌面输出，并非新增一块屏幕。

没有受支持驱动时，“安装签名虚拟显示器驱动”会下载并核验固定版本的官方独立包，然后触发 Windows 管理员安装。安装器复核文件摘要和目录签名，按系统驱动策略只为本次新建设备绑定固定驱动；已有 Mtt 安装不会被此入口覆盖或自动修复。安装失败时保留具体原因，不导入信任根证书、不修改系统签名策略。

## 串流中创建临时屏

两端更新后，源机还需授予该设备“管理服务和连接”权限。显示器标签旁的“+”会创建默认的 1920×1080、60 Hz、SDR 临时屏，并在它进入可采集目录后切换画面。右键“+”或在“设备与屏幕”中打开“管理虚拟显示器”，可调整参数、刷新租约列表和移除屏幕。缺少能力时，“+”显示更新后台或授权的提示。

临时屏属于创建它的整条连接，普通切屏和媒体重新协商会保留它；该连接结束时自动从 Windows 显示布局中移除。若其它窗口也在查看这块临时屏，所属连接结束后它们也会失去该显示源。可结合[多显示器独立窗口](multiple-displays.md)使用。

从串流管理窗口主动移除当前或正在切换的临时屏前，需要先切换到另一显示器。请求结果未知时先刷新列表，避免重复创建。移除表示停用精确目标的桌面输出，驱动及对应 PnP 设备可以继续保留。

## 生命周期与验证范围

管理器按适配器、目标和监视器设备路径记录所有权，只清理所属目标，保留其它活动显示布局。失败的清理记录会保留并允许重试。进程异常终止后不能保证自动清理；源机管理窗口可明确选择遗留的虚拟屏重新提供为空闲槽位。

模拟所有权、真实 Windows 互斥和只读盘点不等于真实增删或驱动安装验收。使用前仍应在自己的驱动和显示环境验证创建、切屏、断流与退出；当前开发验证的具体范围随交付说明提供。

驱动来源：[VirtualDrivers / Virtual-Display-Driver](https://github.com/VirtualDrivers/Virtual-Display-Driver)，MIT 许可；固定包信息见[驱动包清单](../crates/uu-core/src/virtual_display/driver-package.json)。另支持 Zako 的已安装目标，不自动安装其测试证书。CCD 拓扑处理依据 Windows [QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig) 与 [SetDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setdisplayconfig) API。
