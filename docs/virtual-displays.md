# 虚拟显示器（实验性）

Windows 原生共享支持创建临时和持久虚拟显示器。Eclipse 只管理自己创建的设备；物理屏、其它程序的 MttVDD、Zako 等显示器仍列在串流菜单的“已有显示器”，不纳入 Eclipse 的创建数量或删除操作。

## 创建与删除

“服务管理 → 虚拟显示器”和托盘显示入口操作当前激活配置的主机服务。服务未启用或属于另一份配置时，先在服务管理中启用或切换；日常创建、编辑和删除由服务执行，不需要管理员 GUI。关闭管理弹窗不会取消已经提交的操作，关闭 GUI 不停止主机服务。

页面只显示配置列表和右上角加号。加号新增一条未启用的默认配置（1920 × 1080、60 Hz、SDR），可以编辑名称、分辨率、刷新率和 HDR，再点击“启用”接入 Windows。名称默认组合希腊神话人物与天体，例如 Athena Luna、Apollo Sirius。程序固定最多保存 16 条配置，没有可调上限；未启用的配置不创建 Windows 显示器或适配器。

每条配置提供“启用”“禁用”“删除”。禁用会实际卸载这一块 Windows 设备，保留名称、规格、身份和上次位置；重新启用复用同一逻辑身份。删除会同时移除设备和配置。不会为了预留数量在 Windows 中留下断开的显示器。已有配置可在未启用时完整编辑；修改已启用屏幕的规格需先结束主机串流，自定义模式可先禁用、编辑，再启用。

“恢复上次布局”默认开启：启用时优先恢复这块屏的上次位置；首次启用、位置冲突或无法与当前桌面相连时，向主屏右侧的空闲位置扩展。关闭后始终向右扩展。其它已启用的屏幕继续保持启用，已有无关屏幕的位置、模式和颜色设置保持。程序直接应用配置，无需 Windows 显示设置的确认倒计时；不会重放整台电脑的历史显示布局。

“断开串流后自动禁用”控制临时行为。临时和持久使用相同的配置与启用操作；区别只是最后一个相关串流连接结束后，临时屏自动禁用，配置仍保留。串流加号会优先复用规格相同的空闲临时配置，避免反复连接占满列表。多个连接共同查看同一屏幕时，关闭其中一个不会提前禁用它。

“刷新”只读取状态，不重试启用或新建设备。成功提示两秒后消失，等待结果的提示保留；失败可复制诊断详情。请求结果未知时先刷新同一服务，不自动重发设备操作。驱动准备和诊断收在列表下方。

## 驱动准备与升级

主程序不附带驱动。本机管理页面首次启用显示器时，缺少驱动会先询问是否安装；确认后下载固定版本的原始签名包，验证完整摘要与系统签名策略，并在当前登录桌面完成管理员授权和 Windows 首次发布者确认，再继续启用所选显示器。通过 RDP 管理时，安装提示也出现在该 RDP 桌面。只有驱动真正进入 Windows 驱动库才显示已就绪，下载或解压完成不算安装成功；后台遇到需要确认的首次安装会明确报错，不在不可见的物理控制台等待。驱动适配器尚未出现在设备管理器，不等于准备失败：没有已启用屏幕时，Eclipse 不保留空适配器。

“检测驱动”只检查当前状态并显示结果，缺失时询问是否安装；点击“安装驱动”后才下载和准备，本次检测不会创建或启用显示器。取消后被动刷新不会再次弹出安装提示。未完成的旧驱动操作仍应先修复，不会以重新安装替代恢复。下载优先使用官方 Release 地址，失败时尝试同一固定资产的官方 API；两者必须匹配相同 SHA-256。不导入测试证书、不关闭签名检查、不修改其它驱动。

每块屏幕使用独立的原始 Mtt PnP 设备，并在首次启动前设置不同的 UMDF 设备组，隔离驱动进程中的状态。创建与删除只处理这块设备，不使用驱动的全局重载或整批销毁命令。各设备读取独立的一屏配置和 EDID，提供固定逻辑身份派生的序列号与名称；重命名保留身份，完整名称同步至自己的 Windows 监视器属性。EDID 名称最多 13 个 ASCII 字符，自定义长名称会使用短标识。启用和禁用前记录当时的显示状态，完成热插拔后提交预期的自有屏及当次操作前的其它显示状态，补偿 Windows 自动启用或移动旧屏的副作用。只使用本次操作前的即时快照；检测到外部显示器的接入身份发生变化时停止补偿。Windows 的连接组合缓存保存失败不会阻止另一块屏的精确卸载，布局位置由自己的配置保存。

无屏幕主机可能保留 Windows 强制启用的占位输出，甚至仍带有旧屏幕名称。没有监视器接口的强制输出不会作为真实屏幕保存或恢复，因此不会阻止第一块虚拟屏启用；实际连接的显示器仍按精确身份保留。

固定 25.7.23 驱动的多个实例共用维护管道，退出通知可能唤醒其它实例而使自身等待系统超时。仅在卸载已验证的自有独立设备期间，Eclipse 使用不发送数据的短连接唤醒空闲监听；不发送驱动命令，不中断已经连接的维护客户端。

旧版 Eclipse 留下的预留池仅在能核对自身首次安装记录、原签名驱动、配置和精确设备身份时迁移；其它进程仍持有或使用的屏幕会保留。旧池内未使用的目标可以随自有旧适配器一并移除，持久屏按保存规格在新路径恢复。未知来源的 Mtt 安装不会凭名称自动卸载。升级后应先更新实际主机服务；只更新客户端不会改变旧服务的预留池行为。

## 生命周期与恢复

服务启动只恢复已启用的持久配置；临时配置在服务退出后保持禁用。停止服务时移除自有设备，保留全部配置及持久屏的启用意图。复制版本目录可携带配置、逻辑身份和位置记录；本机驱动安装与所有权日志不随目录复制。旧版已保存的持久屏自动迁入配置列表。
管理器持续持有每块目标的跨进程租约。设备的配置标识、逻辑屏幕 ID、随机所有权标记和精确 PnP 实例记录在本机受保护目录，创建提交前先记日志。失败先清理本次设备；无法确认清理时保留记录并停止追加设备。服务重启后只恢复同一配置的记录，不能凭相同显示名称删除设备，也不回放旧的全局显示布局。

原来的物理屏和其它程序的虚拟屏保持独立。删除自有屏幕后，Windows 可能调整自有兄弟屏的位置；程序不会为恢复旧坐标而重新创建已删除的显示器。机器重启、驱动安装、HDR 和真实多屏串流仍须在对应 Windows 环境验收；状态模拟或类型检查不等同于实机验证。

## 串流中创建屏幕

两端更新后，源机还需授予该设备“管理服务和连接”权限。显示器标签旁的“+”优先打开尚未访问的活动屏；没有可用屏幕时，按默认规格新建临时屏。右键“+”可以选择已有显示器、新建与打开方式，以及当前或独立窗口。新标签确认显示源和画面后开放输入，原有连接继续运行。

观看已有虚拟屏和管理虚拟屏使用不同权限。若提示未授权，在源机打开“服务管理 → 配对设置 → 已授权设备”，为该控制端开启“管理服务和连接权限”，再重新连接。连接中的通道、未授权和不支持分别显示对应状态；旧主机没有报告原因时显示状态未知，不直接认定需要更新。通道尚未打开时只等待和刷新状态，不重复创建屏幕。

每个临时屏属于自己的完整连接，移窗、合并和媒体重新协商保留租约。标签右键“断开此会话”只结束该标签，并在没有其它使用者时禁用其临时屏；电脑名菜单或退出快捷键结束当前窗口此设备的全部连接。失败页的关闭操作也只影响当前标签。窗口右上角 X 按整窗范围关闭。[多显示器独立窗口](multiple-displays.md)

## 规格与活动屏幕

“软件设置 → 虚拟显示器规格”提供 1080p60、1440p60、4K60 初始规格，可添加名称、分辨率、含小数的刷新率及 HDR，并选择默认规格。更改预设仅影响之后创建的屏幕；规格保存在本机配置，在串流窗口之间同步。

同一输出只改变位置或主屏时，Eclipse 重建失效的采集并更新输入坐标；等待期间不使用旧画面或旧坐标，保留连接和租约。分辨率、旋转或 HDR 变化涉及采集模式，仍需要重新协商，不能保证原串流持续。需要其它规格时，可以通过“+”新建对应屏幕。
