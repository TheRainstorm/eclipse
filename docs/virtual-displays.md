# 虚拟显示器（实验性）

Windows 原生共享支持管理虚拟显示器。主程序不默认携带驱动；可使用已有的 MttVDD 或 Zako 驱动，也可在源机管理窗口显式安装受支持的签名驱动。其它虚拟显示驱动不会被自动接管。

## 源机管理

Windows 主窗口运行时可从系统托盘右键进入“显示”：管理虚拟显示器、创建虚拟显示器、关闭虚拟显示器、串流结束后保留、重置显示。关闭主窗口是否最小化到托盘仍由软件设置决定。这些入口和“服务管理 → 虚拟显示器”操作同一个后台服务。首次启用服务需系统授权，日常管理无需管理员 GUI；换用完整程序包后在服务管理中应用程序更新。

GUI 不再提供前台、后台选择，配置、配对和显示器租约统一由服务持有。关闭弹窗不取消已提交的操作，关闭 GUI 不停止共享服务。服务尚未启动或需要更新时先在服务管理中处理，不切到另一份本地配置。

“服务管理 → 虚拟显示器”集中显示创建上限和每块已创建的持久、临时显示器。每块屏幕占一行，横向提供名称、常用分辨率、刷新率、HDR、持久开关及保存、删除操作，窄窗口可横向滚动。修改后点击“保存”；“持久”开关决定是否保存并在开机恢复。只修改名称不会改变显示模式，串流期间可以保存；修改规格需先结束此主机的串流。悬停屏幕状态可查看实际模式。列表自动刷新，保留各屏未保存的修改，创建、删除后自动更新数量。

“创建设置”决定下一块显示器的规格和生命周期。托盘创建使用当前默认规格并持续保存；管理页也可创建临时屏。串流新建的临时屏归创建它的连接，持久屏在该连接结束后由服务继续持有。服务内手动创建的临时屏在服务退出时清理。

主程序可解压运行，虚拟显示器驱动仍需首次安装到 Windows。首次显式新建或准备时才会下载、校验并安装固定签名驱动；普通启动不会因为缺驱动而自动安装。准备好的空闲目标不加入桌面布局，因此预留驱动容量不等于已激活桌面虚拟屏。

客户端可以明确创建临时屏或持久屏。临时屏属于创建它的连接，断开后回收；持久屏在创建回执之前保存恢复记录，连接结束后转为源机管理，继续保持并在开机时恢复。保存失败会撤销本次创建；撤销未完成则保留清理记录。移窗、合并和媒体重新协商均不改变屏幕的生命周期。

管理页顶部提供唯一的虚拟显示器上限入口，默认 2 个，范围 0–16，修改后点击“保存上限”。临时屏与持久屏共同计数，手动创建也计入，设置在服务重启后保持。0 禁止新建，降低上限保留已有屏幕和已保存的启动恢复意图。驱动预留的空闲目标不计入已创建数量，实际可用数量还取决于驱动和其它活动输出。

管理页只展示 Eclipse 创建或从自身持久记录恢复的显示器。其它软件创建的虚拟屏不在此管理，也不计入创建上限；串流显示源菜单把它们和物理屏一起列为“已有显示器”。

新建显示器自动使用 Athena、Apollo、Artemis 等名称。临时屏和持久屏共用名称空间，等待恢复的持久记录也保留其名称，避免重复。持久屏恢复时保留保存的名字，用户可在管理页自行修改；名字只用于展示，不改变采集源身份。

对未明确指定生命周期的旧创建接口，源机“串流结束后保留”仍决定默认断流行为；客户端明确选择的临时屏按临时规则回收。已有屏幕可在管理窗口切换是否持续保存，或显式关闭。

保存记录包含规格和对应虚拟目标身份。持久屏可继续存在于共享进程退出之后；进程启动时重新取得该目标的跨进程租约，已有活动目标直接复用，避免重复创建。只有明确保存过、身份唯一且没有被其它进程占用的目标允许如此恢复；其它活动显示器保持独立。Windows 重启后适配器 LUID 可变，恢复仍按虚拟监视器接口和目标身份匹配。

统一服务随系统启动并恢复其保存的屏幕，不依赖 GUI 在登录后启动。驱动被卸载或配置损坏时保留原始记录并报告恢复未完成，不在启动时静默重新安装驱动。首次安装后台会迁移已有保存配置，运行中的目标仍须释放原进程租约后才能由后台重新取得。

“关闭虚拟显示器”只关闭当前管理进程拥有的屏幕，并删除它们的启动恢复意图。“重置显示”在此基础上检查准备事务恢复状态，清除该管理对象的保存记录并关闭断流保留选项；它不会卸载驱动、接管其它进程的显示器或回放历史物理布局。结果未确认的请求不会自动重发。

创建先查找已连接、未加入 Windows 桌面布局且未被其它 Eclipse 进程租用的目标。有可用目标时立即使用，不为增加预留数量而阻挡创建。已有的 MttVDD 或 Zako 目标都不会因为扩容被接管。

显式准备或没有空闲目标的新建请求，按当前创建上限准备驱动容量，默认 2 个；每次新建只激活其中一块屏幕。首次安装会短暂枚举这些驱动目标，完成后未使用目标应处于断开状态。已有较大的驱动池不自动缩减。启动服务、刷新状态或复用空闲目标均不触发安装、扩容。当前固定版本驱动的数量配置需要重新启动适配器才能生效，不能在已有连接、活动 Mtt 输出或目标租约仍被使用时无损扩容。显式准备请求会排队，空闲后执行；现有串流继续。

首次使用或手动卸载后没有驱动时，点击新建即可由已经获得 Windows 系统授权的后台服务下载、核验并安装固定版本的官方签名包；远端创建仍须授予该设备“管理服务和连接”权限。首次安装创建独立的新适配器，可以在已有串流期间执行，持续核对并保留原显示输出；不会因此取消已有连接。重载已有适配器以扩容及恢复未完成事务仍要求空闲。保留的独立管理员安装助手只用于兼容旧流程，不能对运行中的服务绕过统一管理。不要求新用户先手动创建可见屏幕。

准备只增加配置中的屏幕数量，保留已有模式、编码、注释和原始配置备份。既有驱动须匹配受支持的固定签名版本；配置被其它程序修改、出现未知活动输出或原显示布局发生变化时停止操作。准备期间保留全部原活动输出，不重新加载正在使用的适配器，也不接管其它驱动或显卡。源机列表另有“停用现有虚拟屏…”：只有用户明确选择并确认后才停用所选目标，最后一个活动桌面输出及其它进程租用的目标不能停用。只有一个正在使用的 Mtt 桌面或没有活动输出的环境，需要先满足这些显示保护条件。

驱动准备与临时屏租约是两个阶段。临时屏的 CCD 布局增删不保存全局布局数据库。准备空闲池时，只有保存配置仍包含本次明确拥有的 Mtt 目标且能完整保留其它保存策略时，才单独保存空闲基线；不回放旧的全局布局，不放宽 Windows 的模式验证。准备失败尝试精确补偿，未证明恢复时保留目标租约和持久恢复标记，停止自动重试。进程重启后仍能发现中断，恢复标记不会授予新进程接管旧资源的权限。管理窗口提供状态、诊断详情和明确的恢复入口。

“刷新”只读取驱动、容量和屏幕状态。“修复未完成的驱动操作”处理上次安装或容量调整留下的事务：核对操作日志、精确设备身份、配置及当前和保存的显示状态，确认已完成的操作，或尝试撤销该次未完成变更；若驱动已经由外部卸载，则核验后封存旧记录。它不会重装驱动、新建屏幕，也不会恢复历史桌面布局。有串流时，明确提交的修复会等待主机空闲，再执行一次；失败显示诊断并保留证据，不自动重试。“新建”遇到未完成事务会停止，必须先单独修复，修复成功后再明确新建。

Windows 在驱动启停期间会分阶段发布显示路径和监视器接口，暂缺身份不表示设备已消失。准备时先等待完整身份和原屏状态连续稳定，再一次停用本批已取得全部租约的目标，避免逐个停用时其余新目标自动移动造成准备失败；批次之外的显示器仍须保持原状态。容量启动最多等待 45 秒，持续变化会停止操作。精确卸载新设备后也会等待显示状态稳定读回，并记录卸载提交与完成阶段。设备已经移除时，修复继续核验配置和封存记录，不重复寻找或重装旧设备。原屏持续变化仍会阻止准备，诊断会列出变化字段；不会据此回放旧布局。

安装器复核固定文件摘要和目录签名，按系统驱动策略只为本次新建设备绑定固定驱动；已有 Mtt 安装不会被首次安装入口覆盖或自动修复。不导入信任根证书，不修改系统签名策略，不增加采集进程的全局权限。首次驱动安装和批量目标发布仍须在相应 Windows 环境实测，类型检查与状态模型测试不能替代安装验收。

## 串流中创建临时屏

两端更新后，源机还需授予该设备“管理服务和连接”权限。应更新实际 Windows 后台服务并重新连接，普通 GUI 更新不会改变后台能力。显示器标签旁的“+”优先打开未由串流视图拥有的活动物理屏，其次是虚拟屏；没有可用屏幕时，按默认规格新建临时屏。右键“+”可明确选择现有屏幕、持久或临时创建，以及当前或独立窗口。新建在采集开始前完成，新标签确认目录和画面后才开放输入；原有屏幕连接继续。缺少能力时，入口显示更新后台或授权的提示。

临时屏属于新标签自己的整条连接。这个固定视图只显示它绑定的源；移到独立窗口、合并和媒体重新协商都会保留连接及租约。屏幕右键“断开此会话”只结束该屏幕连接并回收其临时屏；电脑名右键或退出快捷键结束当前窗口该设备的全部屏幕连接。若其它窗口也在查看这块临时屏，所属连接结束后它们也会失去该显示源。可结合[多显示器独立窗口](multiple-displays.md)使用。

创建或连接失败页中的“断开此会话”也只关闭当前标签，保留同窗其它显示器；窗口右上角的 X 仍按整窗范围关闭。

固定临时屏视图通过关闭自己的卡片回收当前屏幕。其它管理操作也不能直接移除正在采集或等待切换的源。驱动准备可能需要较长时间；结果等待超过提示期限后，原请求仍保留，界面继续等待回执，避免重复创建。移除表示停用精确目标的桌面输出，驱动及对应 PnP 设备可以继续保留。

## 生命周期与验证范围

管理器按适配器、目标和监视器设备路径记录所有权，持续持有跨进程租约，只清理所属目标，保留其它活动显示布局。目标被外部暂时停用也不会变成可供其它进程重新租用的空槽。失败的清理记录和租约会保留并允许重试。进程异常终止后系统释放租约，但不能保证自动停用临时屏；没有当前租约或自身持久记录的活动输出不会被自动接管。持久屏以保存的意图和新鲜身份重新取得租约。客户端和实际后台服务都应更新后再验证。

若首次安装留下中断日志，之后又手动卸载了驱动，显式修复可重新验证包括 phantom 在内的设备已移除、原始安装文件仍匹配，并稳定核验当前及保存的显示布局。符合条件时只清除精确匹配的旧配置值并封存日志，保留安装证据；不能证明时继续保留恢复门禁，不删除日志绕过。

模拟所有权、真实 Windows 互斥和只读盘点不等于真实增删或驱动安装验收。使用前仍应在自己的驱动和显示环境验证创建、切屏、断流与退出；当前开发验证的具体范围随交付说明提供。

驱动来源：[VirtualDrivers / Virtual-Display-Driver](https://github.com/VirtualDrivers/Virtual-Display-Driver)，MIT 许可；固定包信息见[驱动包清单](../crates/uu-core/src/virtual_display/driver-package.json)。另支持 Zako 的已安装目标，不自动安装其测试证书。CCD 拓扑处理依据 Windows [QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig) 与 [SetDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setdisplayconfig) API。

## 创建规格

“软件设置 → 虚拟显示器规格”提供 1080p60、1440p60、4K60 初始规格，可编辑名称、分辨率、刷新率（支持小数 Hz）及 HDR，或添加自己的规格并设为默认。“+”需要新建时使用默认规格；右键可选择其它规格。窗口与全屏的显示源菜单使用相同设置。

选择规格时将完整参数交给新连接，再由远端驱动验证和创建。编辑、删除或更换默认规格仅影响之后新建的虚拟屏，不改变活动屏幕或其它连接的布局。规格保存在本机应用设置中，在串流窗口之间同步。

## 移动活动屏幕

Windows 应用显示位置或主屏变更时，采集接口可能失效。对于同一输出且像素模式不变的情况，Eclipse 会重建采集并更新物理输入坐标，等待期间不使用旧缓存画面或旧坐标注入，原连接及其临时屏租约继续保留。此行为需要更新实际共享主机，后台共享需更新后台程序。

这与修改创建规格不同。改变活动屏幕的分辨率、旋转或 HDR 会改变采集模式，目前仍需重新协商，不能保证当前串流和临时屏继续保留。若希望使用其它规格，应通过“+”按该规格新建屏幕。

恢复语义参考 Microsoft 的 [AcquireNextFrame](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutputduplication-acquirenextframe) 与 [DuplicateOutput](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgioutput1-duplicateoutput) 说明。
