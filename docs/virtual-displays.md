# 虚拟显示器（实验性）

Windows 原生共享支持管理虚拟显示器。主程序不默认携带驱动；可使用已有的 MttVDD 或 Zako 驱动，也可在源机管理窗口显式安装受支持的签名驱动。其它虚拟显示驱动不会被自动接管。

## 源机管理

源机运行 Eclipse 前台共享或已安装的后台服务时，可从系统托盘右键打开“管理虚拟显示器”。后台服务通过本地管理员通道管理，需要在管理员管理窗口中操作；普通目录中的 GUI 更新不会替换后台进程。

托盘入口明确选择“前台共享进程”或“后台服务”，分别显示和管理对应的租约。操作执行期间保持原管理对象，关闭弹窗不取消已提交的操作。后台服务需要管理员权限，普通窗口会提供打开独立管理员窗口的入口；也可从“管理后台服务”进入。版本查询权限、后台管理权限和驱动可用容量分别判断。

管理窗口可指定分辨率、刷新率及 HDR，新建或移除手动虚拟屏。手动屏由实际共享进程拥有，保留到主动移除或该进程正常退出。前台共享与后台服务各自管理自己的租约。

创建先查找已连接、未加入 Windows 桌面布局且未被其它 Eclipse 进程租用的目标。没有可用目标时，会尝试准备已安装、被禁用且没有活动输出的 Mtt 驱动实例：精确启用该实例，等待目标稳定，再将其准备为空闲目标。后台 System 进程可直接执行；普通前台可在源机管理窗口选择“准备虚拟显示器（管理员）”，确认管理员提示后重试创建。

容量取决于驱动已有的屏幕数量配置；启用一个只配置了一块屏幕的驱动只能提供一块目标。应用不会修改驱动全局数量、重载正在使用的适配器或接管已有活动输出。容量耗尽时会明确报错，更新后台或同步插件不能增加容量。源机列表另有“停用现有虚拟屏…”：只有用户明确选择并确认后才停用所选目标，最后一个活动桌面输出及其它进程租用的目标不能停用。

准备失败时只回滚本次启用的实例。回滚仍失败会明确报告；同一共享进程保留恢复状态，后续变更先重试恢复。恢复记录不跨进程退出保存，一次性管理员准备程序退出后，需按错误在源机核对设备状态。

没有受支持驱动时，“安装签名虚拟显示器驱动”会下载并核验固定版本的官方独立包，然后触发 Windows 管理员安装。安装器复核文件摘要和目录签名，按系统驱动策略只为本次新建设备绑定固定驱动；已有 Mtt 安装不会被此入口覆盖或自动修复。安装失败时保留具体原因，不导入信任根证书、不修改系统签名策略。

## 串流中创建临时屏

两端更新后，源机还需授予该设备“管理服务和连接”权限。显示器标签旁的“+”会新增独立串流标签，由它创建默认的 1920×1080、60 Hz、SDR 临时屏；原屏幕连接继续。新标签确认该虚拟屏的目录和画面后才显示视频、开放输入。右键“+”或在“设备与屏幕”中打开“管理虚拟显示器”，可调整参数、刷新本连接的租约列表和移除屏幕；在此窗口新建也会打开独立标签。缺少能力时，“+”显示更新后台或授权的提示。

临时屏属于新标签自己的整条连接，普通切屏、移到独立窗口和媒体重新协商会保留它。点击新标签的“×”只结束这条连接并从 Windows 显示布局中移除它的临时屏，原屏幕连接保持。若其它窗口也在查看这块临时屏，所属连接结束后它们也会失去该显示源。可结合[多显示器独立窗口](multiple-displays.md)使用。

从串流管理窗口主动移除当前或正在切换的临时屏前，需要先切换到另一显示器。驱动准备可能需要较长时间；结果等待超过提示期限后，原请求仍保留，界面继续等待回执，避免重复创建。移除表示停用精确目标的桌面输出，驱动及对应 PnP 设备可以继续保留。

## 生命周期与验证范围

管理器按适配器、目标和监视器设备路径记录所有权，持续持有跨进程租约，只清理所属目标，保留其它活动显示布局。目标被外部暂时停用也不会变成可供其它进程重新租用的空槽。失败的清理记录和租约会保留并允许重试。进程异常终止后系统释放租约，但不能保证自动停用屏幕；源机管理窗口可明确选择遗留的虚拟屏并确认停用。旧版 Eclipse 没有这项持续租约保护，前台和实际后台都应更新后再验证并存操作。

模拟所有权、真实 Windows 互斥和只读盘点不等于真实增删或驱动安装验收。使用前仍应在自己的驱动和显示环境验证创建、切屏、断流与退出；当前开发验证的具体范围随交付说明提供。
