## 本项目采用什么许可证

原创部分采用 **MIT OR Apache-2.0 双许可**：使用者可以选择其中一种。完整文本见 [MIT](../LICENSE-MIT) 与 [Apache-2.0](../LICENSE-APACHE)。第三方文件保留原来的许可证；根目录许可不覆盖官方软件、第三方商标或第三方服务。

| 方案 | 下游闭源、商用 | 主要义务与差异 |
|---|---|---|
| MIT | 允许 | 分发时保留版权和许可声明，文本简短。 |
| Apache-2.0 | 允许 | 保留许可与适用声明、标注修改；含贡献者专利授权及其终止条件，不授予商标权。 |
| GPL-3.0 | 允许商用 | 分发受 GPL 覆盖的衍生或组合作品时，通常须按 GPL 提供相应源代码及许可。它不是禁止商业使用的许可证。 |

选择双许可延续现有 Rust workspace 声明，便于复用原创客户端代码；并不是对兼容接入合法性的认证。“个人项目、目前不盈利”说明维护者的现状，**不限制下游按开源许可商用，也不构成法律免责**。许可原文：[MIT](https://opensource.org/license/mit)、[Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)、[GNU GPL FAQ](https://www.gnu.org/licenses/gpl-faq.html)。

协议还约定，违反相关条款时可终止、暂停或限制软件使用功能。因此，**即使自行编写全部实现，未经官方授权的兼容接入仍存在协议违约、账号或服务受限的风险**。这里是对条款与项目行为的风险判断，是否成立仍取决于协议订立、条款效力和实际行为；不能由协议单方面禁止就直接推出刑事违法或著作权侵权。

## 没使用官方代码，是否就一定合法

不能据此作出全面保证。独立实现功能与复制受保护的代码、图标、文字或界面表达，是不同的问题。《计算机软件保护条例》第六条将思想、处理过程、操作方法等排除在软件著作权保护之外；第十七条规定一定范围的学习、研究使用。这些规定并不自动授权第三方服务接入，也不直接覆盖所有逆向方式及公开分发行为。[条例原文](https://ipc.court.gov.cn/zh-cn/news/view-407.html)

《著作权法》第四十九、五十条还涉及技术措施及特定例外，不能把“为了互操作”当成无条件的规避和工具分发许可；具体认证、签名机制是否属于该法保护的技术措施，要结合事实判断。[国家版权局法律原文](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

此外，商标混淆、商业秘密、不当获取数据或影响他人网络服务，也有独立风险；应结合现行《反不正当竞争法》及具体行为审查。项目不盈利并不能直接排除这些问题。[2025 年修订法律原文](https://www.cnipa.gov.cn/art/2026/5/20/art_104_206437.html)

本项目没有取得网易授权或法律上的“不侵权”认定。协议分析、客户端身份与签名兼容、公开分发的实际风险，建议由熟悉中国软件与知识产权业务的律师结合实现过程和协议评估。仅访问本人有权控制的设备，不绕过付费、设备所有权或访问权限限制。

## 第三方代码与媒体组件

锁定依赖清单见 [dependency-licenses.md](dependency-licenses.md)，许可文本与上游归属见 [THIRD-PARTY-NOTICES.txt](../THIRD-PARTY-NOTICES.txt)。清单覆盖 Cargo.lock 的所有平台和可选依赖，不等于每一个二进制都链接了全部组件。用 `python3 tools/licenses/generate.py` 更新。

- `vendor/egui-winit`、`vendor/webrtc-dtls` 保留 MIT / Apache-2.0 原文；`vendor/cros-codecs` 保留 BSD 许可。局部修改说明分别保留在 vendor 内。
- 阅读 Moonlight、Sunshine、uu-remote-linux 的机制，不等于取得其代码的宽松许可。如果复制其 GPL 代码或形成受 GPL 覆盖的组合作品，需要遵守相应许可，不能仅换个名字或改写语法后标成 MIT。DTLS 补丁的基础版本、参考线索与改动在 [补丁说明](../vendor/webrtc-dtls/UU-PATCH.md)；这类来源记录应随每次代码引入复核。
- `r-efi` 的表达式含 LGPL **可选项**，同时允许选择 MIT 或 Apache-2.0；不能仅凭其中出现 LGPL 就断定整个应用必须使用 LGPL。
- egui 默认字体包含 OFL、Ubuntu Font Licence 等额外许可，不能只保留 Rust 代码的 MIT / Apache 声明；相关字体文本已收录到通知文件。
- Windows MinGW 的 libgcc / libstdc++ 涉及 GPL 与 GCC Runtime Library Exception。它不等于本应用必须改成 GPL，但要保留适用的运行库声明，分发工具链变化后需重新核对。[例外原文](https://www.gnu.org/licenses/gcc-exception-3.1.html)
- OpenH264 的 BSD 源码许可与 H.264 专利是两回事。本项目从源码构建，不能宣称因此自动获得 Cisco 官方二进制模块的专利费用覆盖；发行二进制或商业化前应另行评估适用国家、专利和分发方式。[Cisco FAQ](https://www.openh264.org/faq.html)

自动生成的清单用于保留通知、辅助审查，不能证明所有依赖和历史代码都已经完成法律审计。
