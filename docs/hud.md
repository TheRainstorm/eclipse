# 串流 HUD

串流菜单的 HUD 子菜单可开关统计并选择 Compact / Detailed。默认档位为 Compact；开关状态沿用已有配置。默认 Ctrl+Alt+S 切换显示（可在输入设置修改），悬停可展开诊断详情。HUD 与悬停内容统一使用英文。

Compact 使用窄幅半透明黑底与青绿色文字，依次显示实际分辨率@目标 FPS、编码、`FPS[recv/dec/rnd]`、`RTT ±`、`Loss`、`Bandwidth`、`enc/dec/rnd` 和预估延迟。窗口较窄时按字段组换行，保持帧率字号。HDR 仅在实际协商 HDR10 时标注。

Detailed 增加解码后端、采集时间、处理 / 网络 / 排队拆分与源刷新率。悬停把会话累计 NACK、RTX、FEC、损坏帧、解码错误和输入反馈分组展示。

| 字段 | 统计含义 |
|---|---|
| FPS recv/dec/rnd | 最近窗口的接收、解码、当前视图绘制帧率；rnd 不等于显示器扫描输出帧率 |
| RTT ± | 控制消息往返时间均值 ± 标准差，最近 32 个样本；不是 ICMP ping |
| Loss | 最近约 500 ms 窗口内，原始 RTP 在乱序宽限期后仍未到达的包数 / 期望包数；FEC 与 RTX 修复不抵消这个值 |
| After repair | 详情中保留的接收器超时未恢复丢包率；原有诊断字段 `loss_ppm` 保持此含义 |
| enc/dec/rnd | 编码、解码调用、UI 准备及渲染提交的窗口均值，单位 ms；GPU 等待可能在提交阶段发生 |
| Est. Total | cap + enc + dec + rnd + RTT/2 + 主机发送等待 + 解码队列 + 画面邮箱等待的均值之和 |
| Known | 某些阶段缺少样本时，仅显示已知部分小计；未知值显示 `—`，不会按零处理 |

Loss 用于观察修复之前的缺包波动。乱序宽限期默认 60 ms，与接收器一致；原始包在宽限期内补到不记丢失，重复包不增加分母，超期原始包单独累计为 late。序号回绕会展开；无法解释的跳变使该窗口显示未知。静止、断流或没有可统计的包时也不伪造零丢包。诊断中的 `network_loss` 记录窗口分子分母和原始包累计数。

这里观测的是应用接收端看到的交付结果，可能来自网络链路、接收缓冲或调度压力，不能只凭 Loss 定位物理链路。结合 RTT 波动、接收 FPS、FEC/RTX 恢复数和修复后损失判断；FEC 恢复成功而 Loss 大于零是正常的。

Est. Total 是已列出阶段的估算，不是实测输入到显示延迟，也不包含应用响应、帧组装、VSync、桌面合成和扫描输出。RTT/2 假设往返链路对称。各阶段取样窗口可能不同，不能据此断言物理显示延迟。
