# 串流 HUD

串流菜单的“更多 → HUD”子菜单可开关统计并选择 Compact / Detailed。默认档位为 Compact；开关状态沿用已有配置。默认 Ctrl+Alt+S 切换显示（可在应用设置修改），悬停可展开诊断详情。主 HUD 保留 FPS、RTT 等通用缩写；悬停详情与应用语言同步。

Compact 使用窄幅半透明黑底与青绿色文字，依次显示实际分辨率@目标 FPS、编码、`FPS[recv/dec/rnd]`、`Bandwidth`、`RTT ±`、`Loss`、`Enc/Dec/Rnd`、视频阶段小计和最近一分钟长间隔。窗口较窄时按字段组换行，保持帧率字号。HDR 仅在实际协商 HDR10 时标注。

Detailed 增加解码后端、采集时间、处理 / 网络 / 排队拆分与源刷新率。悬停详情采用紧凑中文十行：画面、帧率、延迟、网络、排队、恢复累计、异常累计、输入、收包、恢复原因。每行集中一类数据，按类别着色；长说明保留在本页。

| 字段 | 统计含义 |
|---|---|
| FPS recv/dec/rnd | 最近窗口的接收、解码、当前视图绘制帧率；rnd 不等于显示器扫描输出帧率 |
| RTT ± | 控制消息往返时间均值 ± 标准差，最近 32 个样本；不是 ICMP ping |
| Loss | 最近约 500 ms 窗口内，原始 RTP 在乱序宽限期后仍未到达的包数 / 期望包数；FEC 与 RTX 修复不抵消这个值 |
| After repair | 详情中保留的接收器超时未恢复丢包率；原有诊断字段 `loss_ppm` 保持此含义 |
| enc/dec/rnd | 编码、解码调用、UI 准备及渲染提交的窗口均值，单位 ms；GPU 等待可能在提交阶段发生 |
| Video sum | cap + enc + dec + rnd + RTT/2 + 主机发送等待 + 解码队列 + 画面邮箱等待的均值之和；旧版本称 Est. Total |
| Video known | 某些阶段缺少样本时，仅显示已知部分小计；未知值显示 `—`，不会按零处理 |
| Stalls(60s) / 长间隔 | 前台可见串流的新画面提交间隔超过 max(3/预期帧率, 20 ms) 的次数；持续等待只计一次，完成后保留 60 秒 |
| Max gap | 同一窗口内最长的新画面提交间隔，包含进行中的长间隔；不代表显示器实际扫描间隔 |
| 源至发完 | 主机同一 QPC 时钟中，新源画面呈现到最后一个 RTP 写入 API 返回的均值/P95；包含采集前画面年龄及编码、排队与发送，和 Video sum 中的阶段重叠，不能再相加 |
| RTP 跨度 | 同一帧首个到最后一个 RTP 写入 API 返回的均值/P95；区别于生产线程等待发送队列，不代表网卡发完 |

Loss 用于观察修复之前的缺包波动。乱序宽限期默认 60 ms，与接收器一致；原始包在宽限期内补到不记丢失，重复包不增加分母，超期原始包单独累计为 late。序号回绕会展开；无法解释的跳变使该窗口显示未知。静止、断流或没有可统计的包时也不伪造零丢包。诊断中的 `network_loss` 记录窗口分子分母和原始包累计数。

这里观测的是应用接收端看到的交付结果，可能来自网络链路、接收缓冲或调度压力，不能只凭 Loss 定位物理链路。结合 RTT 波动、接收 FPS、FEC/RTX 恢复数和修复后损失判断；FEC 恢复成功而 Loss 大于零是正常的。

Video sum 是已列出视频阶段的均值小计，各阶段不是同一帧的完整关联测量。它没有测量输入设备与输入去程、远程应用响应、等待下次采集、未覆盖的组帧等待、GPU 完成、呈现队列、合成、扫描及像素响应。RTT/2 仅假设往返链路对称，不能据此断言鼠标到屏幕只有几毫秒。详见[原生延迟统计](native-latency.md)。

原生主机支持逐帧遥测时，详情另列上述两个同钟跨度。每个跨度都按自身有效样本计算，不把不同总体的均值相减来填补缺失阶段。遥测超过五秒未更新或来自已退役媒体 epoch 时显示未知；没有源时间戳时，“源至发完”保持未知。它们不能与视频小计再次相加。

长间隔以提交给渲染器的新画面为边界，相同图像的 UI 重绘不计新帧。预期帧率取目标 FPS 和已知源刷新率较小者；165 FPS 时阈值为 20 ms，60 FPS 时为 50 ms。失焦、最小化、切屏、切换设备及帧率改变会重置比较基线，恢复后至少收到两帧才报告数值；媒体换代清空该轨道统计。详情显示阈值、当前连续观测时长及进行中的等待。观测不足一分钟时仍显示实际次数，不外推为每分钟发生率。

v0.20.3 起，暂停观测会保留此前已显示的持续停图记录及最近一次前台观测到的等待长度，直到这条记录超出 60 秒窗口。后台停留时间不会继续累加，恢复后不会把同一次停图再计一遍；未在前台观察到的暂停间隔不转成停图记录。每个间隔按发生时的预期帧率判定，详情中的阈值是当前值。

源空闲、采集节拍、传输丢帧、解码或 UI 调度都可能产生长间隔；计数不会直接把原因归到网络，也不能检测内容内部的动画卡顿或物理屏幕扫描异常。诊断元数据的 `video_continuity` 保存同一统计口径。

悬停面板以当前串流客户区为边界，最大宽 1120、最大高 310 个逻辑点；小窗口进一步缩小，长行换行，超高内容在面板内滚动。移入面板后可继续查看与滚动。v0.20.1 移除额外标题与复制按钮，分类和数据首行对齐；可拖选分类或字段并按 Ctrl+C。点击详情后键盘留给本地选择与复制，点击画面、Escape 或失焦后按现有规则释放详情的键盘占用。

延迟行中的网 / net 为 RTT/2 估计，排 / que 为发送等待、解码队列、画面邮箱三项之和。网络行保留 RTT，不再重复展示单程字段。源刷新率来自主机枚举的显示器模式，未知或旧主机的零值显示为缺省，而不是 0 Hz。
