# 串流 HUD

串流菜单的“更多 → HUD”子菜单可开关统计并选择 Compact / Detailed。默认档位为 Compact；开关状态沿用已有配置。默认 Ctrl+Alt+S 切换显示（可在应用设置修改），悬停可展开诊断详情。主 HUD 保留 FPS、RTT 等通用缩写；悬停详情与应用语言同步。

Compact 使用窄幅半透明黑底与青绿色文字，依次显示实际分辨率@目标 FPS、编码、`FPS[recv/dec/rnd]`、`Bandwidth`、`RTT ±`、`Loss`、视频端到端、输入响应与注入确认，以及最近一分钟长间隔。窗口较窄时按字段组换行，保持帧率字号。HDR 仅在实际协商 HDR10 时标注。

Windows 原生 D3D 呈现路径在双方协商端到端扩展后，默认查询 DXGI PresentCount 回执，并按同帧身份和跨机校时生成“DXGI回执估测”。显示区间从该图像最早已知提交前到首次读到对应回执后；它不以 Present 返回、GPU 完成或刷新率推算显示时刻。**这是有平台统计假设的经验区间，多显示器或其它全屏应用可能使 DXGI 统计不可靠，不能宣称为平台保证的硬误差界。** 缺少帧身份、源时间、有效校时或回执时保持未知，主机未协商扩展时显示“不支持”；纯 WGL 等尚无回执的路径不会回退阶段和。生成预览只检查布局，不是实测结果。

Detailed 增加解码后端、采集时间、处理 / 网络 / 排队拆分与源刷新率。阶段小计只保留为详情中的诊断。悬停详情按画面、帧率、视频端到端、阶段小计、网络、排队、恢复累计、异常累计、输入响应、收包、恢复原因分类，与应用语言同步；分类和数据首行对齐，每类按颜色区分。

| 字段 | 统计含义 |
|---|---|
| FPS recv/dec/rnd | 最近窗口的接收、解码、当前视图绘制帧率；rnd 不等于显示器扫描输出帧率 |
| RTT ± | 控制消息往返时间均值 ± 标准差，最近 32 个样本；不是 ICMP ping |
| Loss | 最近约 500 ms 窗口内，原始 RTP 在乱序宽限期后仍未到达的包数 / 期望包数；FEC 与 RTX 修复不抵消这个值 |
| After repair | 详情中保留的接收器超时未恢复丢包率；原有诊断字段 `loss_ppm` 保持此含义 |
| enc/dec/rnd | 编码、解码调用、UI 准备及渲染提交的窗口均值，单位 ms；GPU 等待可能在提交阶段发生 |
| 视频端到端 / Video E2E | 同一源画面从主机源呈现到客户端系统显示的估测；帧身份、时钟映射和回执完整时报告 `≈均值 ±误差 ms` 并标出显示方法，缺失时未知 |
| 误差与方法 | 区分系统显示回执、刷新区间与 DXGI回执估测。`±` 包含跨机校时、显示区间半宽和微秒舍入；DXGI 方法仅在统计可信假设下成立，不是多屏平台硬界，也不是 RTT 标准差 |
| 阶段小计 / Stage sum | 详情中 cap + enc + dec + rnd + RTT/2 + 主机发送等待 + 解码队列 + 画面邮箱等待的均值之和；旧版本称 Video sum 或 Est. Total |
| 已知阶段小计 / Known stage sum | 某些阶段缺少样本时，仅显示已知部分诊断小计；未知值显示 `—`，不会按零处理，也不替代主项 |
| 输入响应 / Input response | 输入事件到对应画面显示的因果测量尚未接入，视觉响应保持 `—`；与视频端到端分别显示 |
| 注入确认 / Injection ack | 抽样输入发出，经主机系统接受注入，再收到确认的往返时间；不证明应用已响应或对应画面已显示 |
| Stalls(60s) / 长间隔 | 前台可见串流的新画面提交间隔超过 max(3/预期帧率, 20 ms) 的次数；持续等待只计一次，完成后保留 60 秒 |
| Max gap | 同一窗口内最长的新画面提交间隔，包含进行中的长间隔；不代表显示器实际扫描间隔 |
| 源至发完 | 主机同一 QPC 时钟中，新源画面呈现到最后一个 RTP 写入 API 返回的均值/P95；包含采集前画面年龄及编码、排队与发送，和阶段小计中的阶段重叠，不能再相加 |
| RTP 跨度 | 同一帧首个到最后一个 RTP 写入 API 返回的均值/P95；区别于生产线程等待发送队列，不代表网卡发完 |

Loss 用于观察修复之前的缺包波动。乱序宽限期默认 60 ms，与接收器一致；原始包在宽限期内补到不记丢失，重复包不增加分母，超期原始包单独累计为 late。序号回绕会展开；无法解释的跳变使该窗口显示未知。静止、断流或没有可统计的包时也不伪造零丢包。诊断中的 `network_loss` 记录窗口分子分母和原始包累计数。

这里观测的是应用接收端看到的交付结果，可能来自网络链路、接收缓冲或调度压力，不能只凭 Loss 定位物理链路。结合 RTT 波动、接收 FPS、FEC/RTX 恢复数和修复后损失判断；FEC 恢复成功而 Loss 大于零是正常的。

可用的视频端到端测量要求按同一帧的源身份、编码输出 PTS 和实际 RTP 身份关联两端。跨机 QPC 或单调时间戳不能直接相减：四时间戳交换利用路径延迟非负约束偏移上下界，不假设往返对称，再按相对时钟漂移上限扩大区间。详情暴露当前漂移假设；当前为 1000 ppm 的工程上限，不是操作系统保证的精度。源时间或校时样本超过五秒后不再映射，端到端窗口只保留最近三秒实际显示的有效样本，晚到遥测不会让旧显示重新变新。

可用时，均值及 P50/P95 来自同帧延迟区间中点的估测，必须结合误差和显示方法解读，中点不是精确时间。即使有系统显示回执，也没有测量物理面板扫描后的像素响应，更不能把它等同于鼠标到屏幕响应。完整物理延迟仍需外部测量。详见[原生延迟统计](native-latency.md)。

DXGI Count 跳跃只接受明确报告的 ID，不认定被跳过的图像没显示；重复回执不增加样本。统计全零、非 S_OK、DISJOINT、计数倒退或回绕、元数据缺失及窗口/surface/媒体/观测换代会退役旧关联，缓存旧图像不会借新提交伪造首次显示。不要求刷新计数非零，也不调用 DwmFlush 或新增 GPU 等待。原始 Present profiling 开关仍独立控制后台文件，和默认估测共用同一次查询。

阶段小计是已列出视频阶段的独立窗口均值，各阶段不是同一帧的完整关联测量。它没有测量输入设备与输入去程、远程应用响应、等待下次采集、未覆盖的组帧等待、GPU 完成、呈现队列、合成、扫描及像素响应。RTT/2 仅假设往返链路对称，不能据此断言鼠标到屏幕只有几毫秒。

最近三分钟曲线的首项只记录视频端到端估测，竖线表示误差范围；其余项目仍是独立阶段窗口均值，网络项目明确为 RTT/2。未知端到端样本留空，不用阶段和或零补齐。连接、媒体、轨道或显示观测代次改变时重新记录，显示方法改变也不连接旧数据；采样间隔超过一秒时也断开曲线。

原生主机支持逐帧遥测时，详情另列上述两个同钟跨度。每个跨度都按自身有效样本计算，不把不同总体的均值相减来填补缺失阶段。遥测超过五秒未更新或来自已退役媒体 epoch 时显示未知；没有源时间戳时，“源至发完”保持未知。它们不能与视频小计再次相加。

长间隔以提交给渲染器的新画面为边界，相同图像的 UI 重绘不计新帧。预期帧率取目标 FPS 和已知源刷新率较小者；165 FPS 时阈值为 20 ms，60 FPS 时为 50 ms。失焦、最小化、切屏、切换设备及帧率改变会重置比较基线，恢复后至少收到两帧才报告数值；媒体换代清空该轨道统计。详情显示阈值、当前连续观测时长及进行中的等待。观测不足一分钟时仍显示实际次数，不外推为每分钟发生率。

v0.20.3 起，暂停观测会保留此前已显示的持续停图记录及最近一次前台观测到的等待长度，直到这条记录超出 60 秒窗口。后台停留时间不会继续累加，恢复后不会把同一次停图再计一遍；未在前台观察到的暂停间隔不转成停图记录。每个间隔按发生时的预期帧率判定，详情中的阈值是当前值。

源空闲、采集节拍、传输丢帧、解码或 UI 调度都可能产生长间隔；计数不会直接把原因归到网络，也不能检测内容内部的动画卡顿或物理屏幕扫描异常。诊断元数据的 `video_continuity` 保存同一统计口径。

悬停面板以当前串流客户区为边界，最大宽 1120、最大高 310 个逻辑点；小窗口进一步缩小，长行换行，超高内容在面板内滚动。移入面板后可继续查看与滚动。v0.20.1 移除额外标题与复制按钮，分类和数据首行对齐；可拖选分类或字段并按 Ctrl+C。点击详情后键盘留给本地选择与复制，点击画面、Escape 或失焦后按现有规则释放详情的键盘占用。

阶段小计行中的网 / net 为 RTT/2 估计，排 / que 为发送等待、解码队列、画面邮箱三项之和。网络行保留 RTT，不再重复展示单程字段。源刷新率来自主机枚举的显示器模式，未知或旧主机的零值显示为缺省，而不是 0 Hz。
