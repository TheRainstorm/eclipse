# 客户端配置、服务端设置与连接服务

从 0.14 开始，默认进入“设备”。本机可以同时作为控制端和被控端，设置按角色分别保存。

| 位置 | 管理内容 | 生效范围 |
|---|---|---|
| 设备 | 连接地址、上次成功连接时间、上次画面、客户端配置选择 | 当前设备 |
| 设备右键 → 配置编辑 / 详情 | 多个命名配置，可编辑、复制、删除 | 这台设备的下一次连接 |
| 串流窗口 → 设置 | 临时调整当前串流 | 当前会话 |
| 服务管理 | 连接、输入、音视频、编码器、服务运行及会话 | 本机被控服务 |
| 服务管理 → 连接服务 | IP 端口、UU 账号、每台自建服务器、启停及自启 | 本机服务入口 |
| 应用设置 → 常规 / 外观 / 快捷键 / 设备发现 | 语言及软件自启动、壁纸、本机快捷键、自动发现 | 本软件 |
| 应用设置 → 关于 | 版本、构建、平台、许可、项目链接与诊断 | 本软件 |
| 顶部 UU 兼容 | 官方远程协助与官方设备列表 | UU 兼容通路 |



软件设置按左侧分类编辑，切换分类保留草稿；“恢复默认”只重置当前分类，“保存并应用”统一保存全部草稿。

## 客户端配置

未指定独立配置时使用默认配置。设备右键选择“配置编辑”可创建这台设备的独立配置；可以保存“桌面 4K”“移动网络”“游戏”等多个配置，在右键的“配置选择”中切换。

每次打开原生串流窗口时固定读取所选配置。随后编辑设备配置不会改变已经打开的窗口；串流内的临时调整也不会覆盖全局默认或设备配置。已有窗口仍保持自己的会话配置，需要关闭后重开才会使用设备新选择的配置。删除正在选择的配置会恢复为继承全局默认。

UU 兼容串流的快捷设置和“串流设置”会保存到客户端偏好，下次打开继续使用。保存只更新串流偏好，保留主页随后修改的软件设置；异常配置文件保留原样并提示保存失败。

分辨率设置限制输出视频尺寸，保持源画面比例，不放大较小的源画面，也不更改被控端系统分辨率。输入仍按照原始桌面范围定位。软件缩放会增加处理工作，保持原始分辨率可避免这部分开销。

串流菜单按“画面”和“编码”分组：画面包含分辨率、常用30/60/120/165帧、其它帧数与垂直同步；编码包含格式、当前实际编码及码率。声音使用滑块和百分比输入框，输入页包含手柄与键盘相关设置。全屏悬浮入口默认开启，Ctrl+Alt+Shift+H只切换当前窗口，不再保存为设备偏好。

新配置默认选择“推荐码率（LAN Quality）”，按原生串流的实际输出分辨率、FPS 和最终编码自动计算，设置页与悬浮菜单显示推荐值。手动档和自定义值保持固定。各编码的参考表、适用范围及 UU 兼容模式区别见 [推荐码率说明](bitrate-recommendations.md)。

远端提供输入能力时，“输入”和“安全”入口在菜单内暂停转发、失焦或仅观看期间仍保持可见。调整控制偏好不会自动获得远端控制权；进入菜单仍释放远程输入，离开后按当前授权和捕获状态恢复。

新 Windows 原生两端支持独立的远端光标，可在“输入”中切换“仅远端”和“本地和远端”，新配置默认仅远端。位置按源屏幕映射，显示不再依赖客户端本地鼠标位置；模式、兼容性和延迟范围见[原生光标说明](native-cursor.md)。

画面菜单可即时切换垂直同步；串流设置中保存也会立即应用。平台拒绝修改时保留实际状态并显示原因。解码方式在此设备下次连接时生效，每个会话独立选择。

服务运行和串流期间也可以编辑服务端配置。保存仅更新下次启动使用的配置，当前串流继续使用启动时的设置。“保存并重启服务”会先停止所有当前串流并释放旧监听，再加载已保存配置启动；客户端随后可以重新连接。连接入口与端口更改同样在下次启动生效。

原生串流设置的“连接信息”显示主机上的会话。主机可分别授权每台设备的键盘、鼠标、手柄和剪贴板；更改授权会断开受影响设备并释放输入，重连后生效。“管理服务和连接权限”是独立授权，旧控制权限不会自动获得管理能力。获得此权限后，客户端可在串流设置里管理连接和编辑远端服务配置；保存时检查版本，避免覆盖其它窗口的新修改。保存并重启需先收到客户端的保存回执，再停止服务。更改连接端口后需同步更新设备地址。


## 多设备串流窗口

新连接默认加入已有串流窗口，顶部按设备分组显示各自显示器。点击设备或显示器切换当前会话；拖动设备名称会连同其显示器调整顺序。将设备拖出窗口或在设备名称右键选择“移到独立窗口”，会迁移已有会话，保持媒体连接和当前画质设置。

客户端按设备记住最后成功切换的远端显示器，重连或重新打开窗口后自动恢复。没有保存记录时使用服务器的“初始显示器”；保存的屏幕暂时不存在时使用当前可用屏幕，并保留原选择。切屏失败或仍在等待新画面时不会覆盖记录。此选择独立于客户端画质配置，不更改远端系统显示布局。

客户端默认可以在共享期间切换其它显示器，切换时保留当前帧率与码率。支持原生采集协议的 Wayland 合成器会列出真实显示器名称和尺寸；仅支持系统门户的桌面仍按系统要求选择和授权屏幕。

每个设备独立持有解码、声音、输入、HUD 和临时设置。只有前台窗口的当前设备接收键盘、鼠标、手柄和剪贴板；切换时先释放原设备输入。关闭一个设备或窗口仅断开其中的会话。多个窗口独立按需绘制，后台标签的解码结果由有界邮箱保留最新帧。

主页与串流工作区分别运行。再次打开已连接设备会激活它所在的窗口和标签。工作区使用受当前用户权限保护的本机端点和随机能力令牌，双方校验 HMAC 后才传递有界连接请求；协助验证码不写入端点文件、启动参数或日志。

## 原生画质协商

IP、UU 寻址和自建服务器入口使用同一套原生画质规则：

1. 客户端声明经过解码探针确认的格式，以及帧率、输出分辨率、可选码率和编码偏好。
2. 主机保留编码格式和访问授权策略；帧率、码率由每个客户端决定。自动码率按输出尺寸和客户端目标帧率计算，不读取旧主机配置的码率上限。
3. 主机在实际输出尺寸下初始化编码器，仅回报初始化成功的格式。明确选择的格式不可用时会报错；自动选择可使用允许的其它格式。
4. 帧率和码率可在现有连接内更新；分辨率或编码改变时先释放输入和旧连接，再重新协商。统计和诊断记录实际使用参数。

新原生两端可在同一串流中调整帧率和码率，不需要重连传输；分辨率或编码切换仍重新协商。改变帧率时更新采集节奏，必要时建立新的编码参考链并发送关键帧。客户端提供 5–240 FPS 和自定义码率，主机不再提供最大帧率、默认码率、最大码率设置；旧配置中的这些值只为读取兼容而保留，不再截断请求。

原生客户端的“编码 → 码率模式”提供“跟随主机”、CBR 和 VBR。主机设置决定默认模式；客户端的明确选择只作用于自己的会话，不写回主机配置。新两端可在当前连接内切换，必要时重建编码器并发送关键帧；初始化失败保留原编码器和画质并显示原因。VBR 峰值随目标码率调整为两倍，目标码率仍由客户端设置。该选择不应用于 UU 官方兼容串流。

码率模式使用独立能力协商。旧客户端继续使用主机默认；旧主机不提供切换，明确请求该功能时提示升级或改为跟随主机，不静默显示为已生效。软件编码等后端不支持 VBR 时会返回实际错误。

实际输出取决于显示器、采集接口、编码器和网络性能。编码 API 的参数范围、帧缓冲预算及格式 level 仍会校验：例如 H.264 level 5.2 支持 1080p120，但 4K120 超过其预算，需要支持该组合的 HEVC / AV1 后端。无法应用时返回具体错误。旧主机保持原有协商与重连行为，需更新两端才能即时调节。

扩展信息放在可选 SDP 属性中，保留原有严格信令 JSON。旧主机忽略新请求并继续使用自己的参数；旧客户端连接新主机时使用主机默认设置。原生媒体仍是 WebRTC 的 UDP / DTLS-SRTP，不因此切换传输协议。UU 官方兼容模式保留自身的控制协议，原生扩展不会发送给官方主机。

## 服务运行与连接入口

IP 直连默认启用，UU 和每台自建服务器独立启用。启动本机服务时只运行启用的入口，禁用 IP 时不建立其服务或发现监听。所有入口共用本机身份、授权表和会话管理。

顶部提供设备列表、服务管理、UU 兼容与应用设置四个入口。互联网图标打开服务管理：绿色表示运行，灰色表示停止，异常入口以红色提示；启停按钮位于连接服务页。入口登录或网络失败会在连接服务页显示，运行状态不代表每个入口都已经连通。

“打开软件时自动启动服务”只控制主页启动后的行为，不创建操作系统启动项，也不会让每个串流子窗口再启动一份主机。运行中也可保存入口和采集编码设置；下次启动生效，或选择保存并重启。

入口开关控制本机接受连接和发布设备。只控制另一台设备时，不需要先启动本机服务。首次配对、撤销授权和观看 / 控制权限规则保持一致，详见[设备连接与授权](device-connection-and-trust.md)。

UU 登录成功或恢复已有登录后，会自动加载账号设备列表，无需先打开 UU 兼容页。在“添加设备 → UU 账号”中可直接选择设备，也可刷新列表；加载中、空列表和请求失败分别显示，不会因此把已有登录当成未登录。手动输入设备编号仍可使用。

“UU 账号连接服务”明确显示已登录或未登录：未登录时可点击登录，已登录时可登出，与 UU 兼容页共用账号。入口开关不限制登录操作。登出保留本机注册身份、设备配置和原生配对授权，清空账号设备列表；正在使用 UU 入口或等待重启到 UU 入口的本机共享会停止，当前未使用 UU 的共享不受尚未生效的入口设置影响。


## 设备预览与壁纸

连接时间在收到首个解码画面后记录。退出或断线时保存远端视频的最后画面缩略图，不保存菜单、HUD 或本机整个桌面。正常串流期间不额外截图或逐帧回读。预览失败时保留上一张可用图片；缩略图只保存在本机用户目录，移除设备记录时清理对应图片。

设备以壁纸上的缩略图卡片显示，单击连接，右键管理。设备身份归并依据已验证公钥，连接时间、配置和预览随身份归并；同名设备不会自动合并。

设备卡片显示在线、离线或状态未知，约每 5 秒刷新。IP 入口检查 Eclipse 服务公开信息，UU 入口查询当前账号设备状态，自建入口通过带访问凭据的在线查询检查设备；任一入口在线即显示在线。所有入口明确不可达时卡片变暗，仍可单击连接或右键编辑、刷新。未登录、查询失败或旧版自建服务不支持查询时显示状态未知，不据此判定离线。在线状态不替代配对授权，也不保证被控端当时有可采集的桌面。

设备详情可选择“固定当前截图”，保留当前预览；取消固定后，下次串流结束时恢复更新。固定预览只影响本机设备卡片。

壁纸接受直接返回 JPEG / PNG 的 HTTP / HTTPS 图片地址，默认使用 `https://picsum.photos/1920/1080`，与 Moonlight V+ 的摄影壁纸入口一致。这是可替换的图片接口，不是 Moonlight 官方云服务。壁纸缓存在本机，每日检查更新，也可在应用设置里手动刷新或关闭；网络失败时使用缓存或内置蓝色背景，不妨碍连接设备。

## 升级与回退

旧客户端偏好保留原有默认值、光标模式和端口迁移规则。设备连接配置升级为第 5 版，首次修改之前保存一份私有的第 2 / 3 / 4 版原始备份。旧默认端口迁移到 TCP 48998、UDP 48999，自定义监听端口保留。账号、设备私钥和已有配对不因界面调整重新注册。

旧版本不能读取新版设备配置。回退前先退出应用并保留全部用户数据，再恢复相应旧版备份；不要让旧版本覆盖新版的连接记录。

服务端默认编码支持“自动协商”。服务器明确选择时优先使用服务器格式；服务器自动时由客户端明确选择格式；双方自动按 AV1 → HEVC → H.264 尝试允许且双方可用的格式。明确指定的格式不可用时显示失败原因，不静默降级为 H.264。原生画质协商成功后，串流菜单提供码率、帧率、分辨率与编码快捷设置，更改需要重连时自动应用。


服务管理的“编码”页可保存厂商参数，本机与远程编辑使用相同设置，下次启动服务生效：

| 厂商后端 | 参数 | 默认 |
| --- | --- | --- |
| AMD AMF（Windows） | 速度、均衡、画质预设 | 速度；保持超低延迟用法和无 B 帧 |
| Intel oneVPL / QSV | Target Usage 1–7（1 偏画质、7 偏速度）；低功耗引擎自动、启用、停用 | 7；自动优先低功耗引擎 |
| NVIDIA 驱动 MFT（Windows） | 自定义画质/速度 0–100（0 偏速度、100 偏画质） | 关闭自定义，尽力请求速度优先 |

这些设置只用于实际选中的 GPU。明确设置的参数必须通过驱动检查和读回，不能应用时说明失败原因；自定义参数不会通过软件回退伪装为已生效。提高画质可能增加编码时间，需按实际统计调整。NVIDIA 当前使用 Windows Media Foundation 驱动接口，其参数不是 NVENC P1–P7 预设。Linux VA-API 后端不接受 AMD/NVIDIA 自定义参数；Intel 自定义参数使用 QSV。

参数语义参考 [AMD AMF 头文件](https://github.com/GPUOpen-LibrariesAndSDKs/AMF/tree/v1.4.36/amf/public/include/components)、[oneVPL 参数](https://github.com/intel/libvpl/blob/674d015bcb294bc39fa276e99a652ea045423e82/api/vpl/mfxstructures.h)及 [Windows QualityVsSpeed](https://learn.microsoft.com/en-us/windows/win32/codecapi/avenccommonqualityvsspeed-property)。设备配置从 v4 读入时使用默认参数，首次保存前保留原内容的私有备份；回退旧程序前按旧版备份恢复。


服务管理新增“配对设置”页，集中管理设备名称、配对密码、预授权公钥、本机公钥复制与已授权设备。粘贴有效的 Eclipse / SSH Ed25519 公钥时，自动从末尾备注填入设备名称；手动修改的名称会保留。密码保存在独立私有凭据文件中，点击“保存配对密码”后用于后续新配对；不会包含在普通服务配置快照中。密码验证后的权限由主机设置，临时码授权随串流结束失效。首次连接的选择和升级要求见[设备连接与信任](device-connection-and-trust.md)。


串流窗口“输入”菜单集中提供光标显示、指针移动和手柄选项。Ctrl+Alt+Shift+C 在“仅远端”和“本地和远端”间切换；Windows 原生光标合成与旧主机回退规则见[光标说明](native-cursor.md)。“画面”中的“优先 HDR”默认开启，实际状态由两端能力及显示输出决定，详见 [HDR 串流](hdr.md)。

### 实验性 PyroWave

v0.19.0 起，主机在允许的编码中启用 PyroWave 后，客户端可明确选择此格式；默认自动协商不选择它。当前支持 SDR、4:2:0、CBR 帧预算，需要较高网络带宽，详见 [PyroWave 范围与实测](pyrowave.md)。两端须更新完整安装包并重启相应程序/共享；旧配置不会自动勾选新格式。

串流菜单的 HUD 子菜单提供 Compact / Detailed 两档，悬停展开分组诊断；原始网络缺包与修复后剩余缺包分别统计，字段和预估延迟口径见 [HUD](hud.md)。

客户端配置中的输入页支持定制快捷键并显示内部冲突；当前串流、默认配置和命名配置按各自范围保存，见 [客户端快捷键](keyboard-shortcuts.md)。

## 应用语言

在“应用设置 → 软件设置 → 常规”中选择简体中文或 English，保存并应用后立即更新界面。已打开的新版串流窗口会在后台同步语言；精简 HUD 保持英文缩写，详情和曲线说明随语言切换。语言独立于设备画质配置，旧配置默认简体中文。用户填写的名称、远端文本及操作系统界面保留原样。升级后请完整退出旧主页和串流窗口，避免旧版本保存时丢失新字段。
