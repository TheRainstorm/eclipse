# 原生剪贴板（文本与图片）

图形主机共享时勾选“允许文本和图片剪贴板同步”，控制端连接后在悬浮菜单的“剪贴板”或完整“输入”设置中开启“同步剪贴板（文本和图片）”。两端默认关闭；原生许可独立于兼容模式，同窗口重新连接和切换编码保留当前选择，也可以保存到设备的客户端配置供下次使用。CLI 主机暂不提供系统剪贴板后端。

仅当前前台串流同步，文本最多30 KiB UTF-8，图片支持最多8 MiB PNG、16M像素及8192像素边长；不传输文件或富文本，不支持包含 NUL 的文本。新版本两端会自动协商图片能力，旧端仍使用文本通道。Windows 接入 PNG / DIB / DIBV5，Linux 使用 X11 / Wayland 剪贴板服务。控制端手动选择仅观看时可以接收已获许可的主机文字和图片，不发送本地内容。开始同步时以控制端当前文本为初始来源，主机已有内容先保留为基线，不主动广播；之后双向跟随复制操作。失焦时不读取系统内容，重新获得焦点时比较保留的内容指纹：主机在暂停期间的新复制可以传回，控制端未变的旧值不会重新广播覆盖它。不会在日志、诊断报告或命令参数中记录剪贴板正文。

剪贴板使用单独的加密可靠有序 SCTP 通道，保留键鼠消息的小包限制。双方确认许可后才传送正文，文字和图片共用一条有序内容流，待发送与待写入内容都只保留最新一项。图片按8 KiB分片，设置传输积压和10秒超时上限，完整接收、检查尺寸并成功解码后才写入系统；不写入半张图片。两端复制使用内容修订号排序，同时复制时按固定规则收敛，过期图片不会覆盖更新的文字。焦点或许可改变会更新激活代次，迟到的旧代次消息被丢弃。控制端后台、关闭同步、失联租约到期或会话结束时停用同步并丢弃内部待处理文本，不主动清空系统剪贴板。

旧主机可以拒绝新增通道，视频、声音与输入继续工作。权限只对当前邀请会话有效；剪贴板读写失败也不停止视频。Windows 主机使用共享窗口作为剪贴板所有者；Linux 使用已授权的 X11 / Wayland 剪贴板服务，桌面策略可能限制后台访问。

## 隔离验证

```bash
cargo build --release -p uu-gui --example native_clipboard_probe --features vaapi --locked
python3 tools/native/clipboard_smoke.py \
  --probe ./target/release/examples/native_clipboard_probe \
  --output ./artifacts/native-clipboard-test
```

脚本创建两个独立、有认证的 Xvfb。主机和控制端各自使用自己的系统剪贴板，只复制生成的测试文字，检查默认关闭、双向文字/图片、文字图片切换、仅观看图片接收、后台暂停、重新激活时的收敛、视频继续与退出清理；不会使用工作桌面的剪贴板。核心测试另检查 UTF-8、代次、长度与无效包处理。

Windows CI 另运行 `windows_clipboard_probe --isolated-window-station`，必须成功创建并核对全新的非交互窗口站后才执行剪贴板操作，检查中文/表情、透明PNG/DIBV5读写、主机初始基线、后台暂停、控制端前台限制和线程释放。各窗口站拥有自己的剪贴板，依据 [Microsoft 窗口站说明](https://learn.microsoft.com/en-us/windows/win32/winstation/window-stations)；测试不切换用户正在使用的桌面，创建失败即退出，不回退到交互窗口站。该测试程序只作为 CI 验证产物，不进入发布包。
